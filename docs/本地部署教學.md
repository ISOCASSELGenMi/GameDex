# 本機建置與部署步驟

以下用 PowerShell 寫。下面的 `<專案根目錄>` 換成你 clone 的位置，`next build`／`next start` 在 `apps\web` 內跑。

## 一、日常流程（開三個終端機分頁）

**分頁 1：資料庫（前景執行，不能關）**
```powershell
cd <專案根目錄>
npm run db:start
```
看到 `PostgreSQL 已啟動：localhost:54329/sok_studio` 才算好。

**分頁 2：建置**
```powershell
cd <專案根目錄>\apps\web
$env:SCHEDULER_ENABLED = "false"
npm run build
```

**分頁 3：啟動 production 伺服器**
```powershell
cd <專案根目錄>\apps\web
$env:SCHEDULER_ENABLED = "false"
npx next start -p 3100
```
然後開 http://localhost:3100 。

## 二、改了程式之後
- **要看 production 行為**：停掉分頁 3（Ctrl+C）→ 重跑 `npm run build` → 再 `next start`。
- **只是改畫面、想即時看到**：不用 build，直接用 dev 模式，改完會自動更新。
  ```powershell
  cd <專案根目錄>\apps\web
  $env:SCHEDULER_ENABLED = "false"
  npx next dev -p 3100
  ```
  dev 與 `next start` 不要同時佔 3100，擇一。

## 三、停止
- 資料庫：在分頁 1 按 Ctrl+C。如果視窗已經關掉，改用：
  ```powershell
  node_modules\@embedded-postgres\windows-x64\native\bin\pg_ctl.exe stop -D .local\pgdata -m fast
  ```
- 網站：分頁 3 按 Ctrl+C。若是背景跑的，用 `Get-NetTCPConnection -LocalPort 3100` 找 PID，再 `Stop-Process -Id <PID>`。

## 四、注意事項
1. **一定要先開 DB**。沒開的話網站可以啟動，但資料頁會出錯，`/readyz` 也不會是 200。
2. **`SCHEDULER_ENABLED=false`**：`.env.local` 裡是 `true`，不設的話網站啟動後會在本機跑 IGDB 同步等排程，改寫你的資料並消耗 IGDB 額度。純瀏覽時一律設 false。這個環境變數只對當前終端機有效，每個分頁都要設。
3. **build 型別檢查失敗**（出現 `.next/dev/types/validator.ts ... Cannot find module`）：這是 dev 模式留下的過期快取，刪掉再 build：
   ```powershell
   Remove-Item -Recurse -Force .next\dev
   ```
4. **不要用 `npm run dev` 和 `launch.json` 以外的 port 混用**：`.claude/launch.json` 的預設是 3100，換 port 的話書籤、預覽都要跟著改。
5. **不要動 DB 結構與資料**，除非你確定：`db:migrate`、`db:seed`、`npm run job ...` 會寫入開發 DB（目前已套到 migration 0017）。`backfill_company_positions` 還沒跑，且需要 IGDB 金鑰。
6. **不要和測試同時跑**：`npm test` 與 `test:a11y` 共用測試 DB，不能同時跑。e2e 一律加 `$env:PW_CHANNEL = "chromium"`。
7. **Secret**：金鑰在 `apps\web\.env.local`，別貼到對話或其他檔案。
8. **埠被佔用**（`EADDRINUSE`）：上一個 next 還沒關，照第三點的方式結束它。

## 五、快速檢查
```powershell
curl.exe -s -o NUL -w "%{http_code}`n" http://localhost:3100/healthz
curl.exe -s -o NUL -w "%{http_code}`n" http://localhost:3100/readyz
```
兩個都是 200 就代表網站與 DB 都正常。
