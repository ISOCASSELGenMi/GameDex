# 06 前端

Next.js（App Router）＋ TypeScript ＋ Tailwind CSS，單體應用。`app/` 只放薄路由（02），實際內容在 `modules/<name>/ui/`。頁面元件呼叫 Repository／Use Case 函式，**不寫 `db.select()`**。版面的可變區域（header 右側、遊戲頁動作列與區塊）用 UI slot，`catalog` 版面不寫死任何可選功能。

## 首頁

- 儀表板四區：**即將上市**、**最新上市**、**近期活動**、**近期熱門**（accounts 啟用時依 `site_follows_7d`），每區封面卡片橫列、上限 12 筆、「查看更多」連到對應頁。資料由 `getHomeDashboard` 取得，套用 §聚合規則（不另寫一份）。
- 伺服器 HTML 與使用者無關，`s-maxage=60`；HTML 預算 < 200 KB。
- **近期活動**：進行中的活動＋今天起 30 天內開始的活動（D86）。
- **近期熱門**：「即將上市／已上市」分頁切換，兩群各自排名（熱度百分位只在群內可比），預設即將上市（D86）。
- **最新上市的「查看更多」**（D87）：連到時間軸 30 天前所在的那一週（`/timeline?at=<今天−30 天>`，`HOME_RECENT_DAYS = 30`；時間軸以 `at` 日期決定所在 ISO 週）。
- 熱門分頁的兩組都由伺服器渲染進 HTML，切換只改 `hidden`、不重新請求；「查看更多」連結隨分頁（`/trending` 或 `/trending?group=released`）。首頁卡片的火焰圖示共用一份 `<symbol>`（`HeatSprite`／`spriteId`）壓低 HTML；實測（真實資料、48 張卡）約 173～177 KB，餘裕約 23 KB。
- 首頁掛著互動背景與彩蛋層（§互動背景、彩蛋與隱藏主題）；彩蛋 8（連點品牌）只在首頁生效。

## 導覽與 header

第二輪（D85、D87）已實作，Holodex 式，桌機與手機一致，不再有收合抽屜：

- **左側**：站名按鈕（導覽下拉的觸發鈕）＋**依頁面切換的品牌文字**。品牌名依所在區塊決定，三語相同、不翻譯：首頁 `GameDex`、月曆 `GameCalendar`、時間軸 `GameTimeline`、熱門榜 `GameTrend`、遊戲 `GameBase`、平台 `GamePlat`、活動 `GameEvent`、評分 `GameRanking`。子頁跟隨所屬區塊（遊戲詳情→GameBase、平台頁→GamePlat、活動詳情→GameEvent；**公司頁、系列頁歸 GameBase**），帳號、關於、訂閱等沒有自己區塊的頁面顯示 `GameDex`。單一實作為 `catalog/ui/layout/nav-items.ts` 的 `SECTION_BRANDS`／`brandOfPath`；伺服器依路徑輸出（可快取），換頁後品牌文字淡入 150ms（`prefers-reduced-motion` 直接切換）。`<title>` 與站名字典 `ui.site.name` 不變。
- **導覽下拉**：單一陣列（要加項目就加一列），順序即區塊順序：首頁、月曆、時間軸、熱門榜、遊戲、平台、活動、評分。每項為「該語系名稱」加右側小字品牌名（CSS 產生內容，不進可及名稱），目前頁以 `aria-current` 與勾勾標示。`ORG_HOME_URL` 有設定時，組織首頁連結在 < 1024px 收進導覽下拉最後一項。
- **右側**依序：搜尋、**主題**、**語言**、**帳號**；後三者與導覽共四個下拉，共用 `kernel/ui/dropdown.tsx`（disclosure 模式：`aria-expanded`／`aria-controls`、Esc 關閉並還焦點、點外面或 Tab 離開關閉、↑↓／Home／End 移動、同時只開一個）。
  - 主題下拉：跟隨系統／亮／暗，加上**已解鎖**的隱藏主題。偏好存 localStorage（`sok-theme`）、套在 `<html data-theme>`（跟隨系統＝不設屬性，沿用 `prefers-color-scheme`）；`<head>` 內嵌腳本在繪製前套用以免閃爍。
  - 語言下拉：一般連結，不需 JS（§多語系）。
  - 帳號下拉：未登入為登入／註冊；「註冊」依執行時的 `ACCOUNTS_SIGNUP_ENABLED`，客戶端確認未登入後向 `GET /api/v1/auth/public-config`（07）取設定才決定是否顯示（頁面預渲染，不把設定烤進 HTML）；已登入為帳號頁入口與登出。
- **搜尋候選（combobox）**：header、首頁、遊戲頁共用一個元件（`catalog/ui/search/search-combobox.tsx`）。打字時向 `GET /api/v1/games/suggest`（07）取候選，最多 8 筆，每筆顯示封面、標題（依介面語言）、年份、平台；↑↓ 選擇、Enter 進入、Esc 關閉，符合 ARIA combobox 模式，結果數以 `aria-live` 宣告；沒有選取項目時 Enter 照一般表單送出搜尋。候選順序為完全符合 → 開頭符合 → 熱度（限制見 §已知限制）。
- **窄螢幕**：< 480px 品牌只顯示 `GameDex`、按鈕 40px、導覽下拉貼視窗左緣展開；< 640px 搜尋收成圖示，點開展開搜尋列；< 360px 品牌字級縮小且可截斷。無 JS 時 header 放 `<noscript>` 導覽清單（< 640px 且無 JS 時 header 沒有搜尋框，頁面內的搜尋仍可用）。
- 動畫（只動 transform／opacity）：面板 opacity＋scale(0.96)、`transform-origin` 對準觸發鈕、開 180ms／關 120ms；按鈕 `:active` scale(0.97)；hover 效果包在 `(hover:hover) and (pointer:fine)`；鍵盤開啟不做動畫；reduced-motion 無縮放。

## 月曆

- **不用通用行事曆套件**，自己刻 CSS Grid。
- **每個日期一格只顯示一款遊戲**（封面滿版、名稱、平台、標籤），同日多款在**格內左右切換**（按鈕、方向鍵、觸控滑動），格底以點點或「3 / 24」顯示位置；今天有明顯標示；換月有轉場（D84）。
- 伺服器 HTML 只送每天的第一款與當日總數；其他款切換時才由 `GET /api/v1/calendar/day` 載入（07），同一套篩選與 §聚合規則。月曆頁 HTML 預算約 250 KB（改版前整月 1.7 MB）。
- **模糊日期不進格子**，列在月曆下方「本月未定日」區塊，依 `releaseDate` 所在月份歸屬：月精度 → 該月；季／年 → 期間最後一個月。數量 ≤ 24（`UNDATED_OPEN_MAX`）顯示完整卡片與預覽卡；超過 24 的組預設收合，**伺服器端只送熱度最高的前 24 款精簡列**（依 `popularity_score` 降冪、同分依名稱，不是送全部再用 CSS 藏），summary 的款數仍是總數，底下加「查看全部 N 款」連結（純連結，沒有 JS 也可用）。連結目標 `/games?<月曆目前的篩選>&year=<該組期間最後一天所在年>&by=date`（瀏覽頁不適用的參數如 `show` 略過）；月精度、季精度的組也只能對應到該年（瀏覽頁的 `year` 比對遊戲首發日期的年份，沒有月／季維度），所以清單筆數會多於 N（含同年其他月份與精度明確的遊戲）。
- 手機寬度：改為橫向卡片列表，仍是一日一款＋可切換。
- 無障礙：每格 `role=group`、可及名稱含日期與款數；方向鍵切換同日款數；目前顯示的款以 `aria-live` 宣告。
- 支援 §篩選，條件在 URL，切換月份保留。點項目開側邊預覽卡（追蹤按鈕 slot、Discord 活動 slot）。
- **遊戲／活動開關**（D85、2026-10-23 實作）：月曆上方兩個開關（`role=switch`，連結形式，無 JS 也能用），狀態在 `?show=`：未給＝只開遊戲；`show=events`＝只看活動；`show=events,releases`＝兩者；預設值不寫進網址。兩個都關是禁止的（最後一個開著的開關 `aria-disabled` 並附說明）。伺服器不查關掉的那一類（`getCalendarMonth` 的 `includeReleases`；day API 同語意）。切換以 View Transition（type `cal-toggle`）淡入 120ms。

## 時間軸

**以週為單位的垂直中軸**（D84，參考 IGDB timeline）：

- 上一週／下一週、跳到指定日期、回到今天（今天以 UTC 日期計）；網址 `?week=YYYY-Www`（ISO 週，週一起算），舊連結 `?at=YYYY-MM-DD` 取該日所在週。有 JS 時就地切換（`GET /api/v1/timeline/week`＋`history.pushState`），沒有 JS 時是一般連結。
- 每個發售日一張封面卡片，**左右交錯**掛在中軸、以橫線連到日期節點；卡片頂端顯示當日上市數；同日多款沿用月曆的格內切換與 day API。手機中軸靠左、卡片單側。
- 上方平台種類快速篩選＋既有篩選面板。日期只確定到月／季／年的遊戲不在時間軸（請看月曆）。
- 無障礙：`<ol>`、日期節點標題含完整日期、新週載入以 `aria-live` 宣告。HTML 預算 < 200 KB。

**硬體世代時間軸**（後置）：以 `platform_families` 為列、`platform_release_dates` 到 `discontinuedOn` 為條，世代為背景分欄。

## 全部遊戲與分組檢視（`/games`）

D87：沒有另開「全遊戲列表」頁，改造既有 `/games`。預設（`by=none`）仍是所有遊戲的瀏覽清單；`?by=` 切換為分組檢視，與篩選、搜尋、排序並用，這些參數與 `by` 都保留在網址。切換控制是 radio group（`fieldset`＋`legend`，方向鍵切換不做動畫），`<noscript>` 有連結備援；`?by=` 未知值退回 `none`。分組檢視的 canonical 仍指向 `/games`，不進 sitemap。

- **分組單位是「組」**：一頁 6 組（以 `page` 翻組，上限 200 頁），每組首屏 6 張卡，「顯示更多」一次再載 24 張（`GET /api/v1/games/group`，07；API 上限 60）。每組是 `<section aria-labelledby>`＋`<h2>`＋`<ul>`。卡片以封面為主，顯示名稱、首發日、平台縮寫、標籤（傳聞／非主遊戲類型）。
- `date`：組＝首發年月（日／月精度 `YYYY-MM`、季 `YYYY-Qn`、年 `YYYY`），日期未定獨立一組且永遠最後；組的順序跟隨目前排序（`release_date` 由舊到新，其餘由新到舊）。
- `platform`：組＝平台（不含 mobile）；一款遊戲出現在它每個平台組，沒有平台的遊戲不出現；組序＝平台總覽順序（主機→掌機→PC→街機→其他，常用在前）。
- `publisher`：組＝廠商欄位（37 欄＋「獨立／其他」，名單與歸屬見 `docs/design/publisher-groups.md`，唯一實作 `catalog/domain/publisher-groups.ts`，以 IGDB 公司 id 對照表比對）。歸屬規則：**開發商優先 → 發行商 → 其他**，一款遊戲只放一欄，porting／supporting 不參與；`game_companies` 沒存 IGDB 列出順序，所以多個開發商都在名單內時取名單欄位順序最後者（合開作品歸更具體的品牌），函式有給 `order` 時才依 IGDB 順序。
- 組內順序＝目前排序（加 id 平手），「顯示更多」穩定。
- **共用篩選**：分組查詢重用 `buildBrowseConditions`，不另寫一套。查詢分兩段：先取一頁的組清單與每組總數，再只對這些組取每組前 N 張。
- **組 key 是預先計算的**（Z6）：`date` 讀 `games.release_group`、`publisher` 讀 `games.publisher_group`（03），查詢時不重算；`platform` 以整數 `platform_id` 分組。`backfill_game_groups` 跑完前，`date`／`publisher` 會把所有遊戲歸成一組（04）。開發 DB（約 32 萬款）實測，各分組與篩選組合中位數 12～391 ms。
- 動畫：只動 transform／opacity、≤ 250ms；顯示更多的新卡片淡入（鍵盤觸發不動畫）；reduced-motion 關位移。
- 預設排序（熱度）下日期組由新到舊，第 1 頁會從最遠的未來月份開始；想從最舊看起用「上市日期」排序（待決，見 §已知限制）。

## 評分排名（`/ratings`）

D85 追加、2026-10-23 實作。表格式排名（真 `<table>`）：

- **欄位**：IGDB 分數（預設排序欄）、站內玩家平均（accounts 啟用時才有）；Metacritic 啟用後再加 Metascore、Userscore。欄位由擴充點 `ratingColumns`（manifest 欄位，registry 注入 `getCatalogExtensions().ratingColumns`；catalog 內建 `igdb`）註冊，catalog 不寫死模組名；accounts 停用時沒有 players 欄，`sort=players` 退回 igdb。
- **網址**：`?sort=<欄位 id>&dir=asc|desc&minVotes=&page=`＋共用篩選。名次用 `rank()`（同分同名次，與 `dir` 無關）。`page=N` 一次渲染前 N 頁（每頁 50 列，上限 20 頁）；無 JS 時「載入更多」是 `page=N+1` 連結。
- **最低票數**：由使用者在篩選中調整；預設 IGDB 評分人數 ≥ 10（真實資料只剩約 806 款）；玩家平均沿用 `PLAYER_RATING_MIN_COUNT`。
- **排序互動**：欄位標題是 `<button>`，`aria-sort`；切換排序時以 FLIP（WAAPI、只動 transform、250ms、`cubic-bezier(0.77,0,0.175,1)`、可中斷、視窗外的列直接就位）呈現列位置變化，並標示相對上一個排序欄的名次升降（API 帶 `prev=<上一欄>` 由伺服器算）；reduced-motion 或鍵盤觸發時不做位移，只留名次標示；名次變化以 `role=status aria-live=polite` 告知。
- 資料只讀 `ratings`（玩家平均由 accounts 排程 `publish_player_ratings` 寫進去，09），catalog 不 import accounts。
- 篩選面板列完整平台清單（常用平台置頂、其餘收在「更多平台」`<details>`）。2026-10-29 移除原本的「只列常用平台」（`commonPlatformsOnly`）：核取方塊清單已是 HTML 字串，真實資料下 `/ratings` HTML 為 zh-Hant 168,061、en 166,558、ja 172,601 bytes（< 200 KB）。

## 平台頁的「全部遊戲」

`/platforms/[slug]?section=all`（D87）：該平台**所有**上市列，不限天數與上市狀態，日期未定者也列；仍走聚合規則（`buildAggregateCardsQuery`，`from`／`to` 為 null、`precisions` 含 `tbd`），排除項與其他區段一致（傳聞、DLC、取消、beta 階段、mobile）。預設區段仍是 `upcoming`。排序 `date`（新到舊，同日依熱度，日期未定排最後）／`popularity`／`name`（依介面語言的顯示名稱 A→Z；三個區段都可用）；每頁 24、`page`、offset 上限 10000。`all` 區段的資料讀取包在 15 分鐘 `use cache`。

**加速（Z6）**：顯示結果不變，但查詢分兩段。先從預先計算的 `release_picks`（03）決定這一頁是哪 24 款遊戲，再只對這 24 款跑聚合規則。只有地區偏好 WW、篩選為預設、且 `backfill_game_groups` 已完成時走這條路；其他情況退回原本的即時聚合。開發 DB 實測：PC 依日期第 1 頁從 30 秒降到 8 ms，各平台、排序、頁碼最慢 308 ms（PC 依名稱第 100 頁）。

## 聚合規則

`release_events` 是遊戲 × 平台 × 地區 × 階段，不聚合會讓一款遊戲出現十幾次。**月曆、時間軸、Discord `/upcoming`、公開 iCal 共用**，寫成 Repository 單一函式 `repository/release-aggregate.ts`：

1. 每個 (遊戲, 平台, 階段) 挑一筆：來源仍存在（active）優先於 removed（被 IGDB 覆蓋的 manual 為 removed，D75）；其次 `manual` 優先於 `igdb`；其次使用者偏好地區 → `WW` → 最早日期（`DISTINCT ON` ＋ 優先序）。
2. 同一款遊戲、同一天的多個平台合併成一張卡（平台以 chip 呈現）；不同天分開。
3. 地區偏好 = 使用者設定 > 瀏覽器語系推導 > `DEFAULT_REGION_PREF`（`WW`）。

**版本標註與相關內容**（資料見 03 §遊戲詳情補充欄位）：

- 「其他版本」列：有 version 子作時顯示「查看另外 N 個版本」，點開在本頁展開。
- **版本標註**（`editionNotice`）：本身有 `version_title` 且本體已同步 →「這是《X》的 Nintendo Switch 2 Edition」；是版本但無標題 →「…的版本」；`gameType` 非主遊戲且有本體 →「這是《X》的 DLC／重製版…」（en 句型 `Part of X: DLC / Add-on`）並連回本體；本體尚未同步或一般遊戲不標。
- **相關內容**依關係分組，只列有內容的組，順序為 `RELATED_GROUP_KEYS`：版本（editions）、擴充版、DLC、資料片、獨立資料片、重製、高畫質重製（remasters）、移植、合輯、章節／季、追加包。分組對照唯一實作 `catalog/domain/related-groups.ts`（`game_type` → 組：expanded_game→expanded_games、dlc_addon→dlcs、expansion→expansions、standalone_expansion→standalone_expansions、remake→remakes、remaster→remasters、port→ports、bundle→bundles、episode／season→episodes、pack／update／mod／fork→packs；`main_game` 與 `other` 的子作不進任何組）；每組最多 24 款（首發日由舊到新，無日期在後），超過顯示「還有 X 款」。同一款若同時是 `version_parent` 與 `parent_game`，只算 editions。
- **展開機制**：內容 SSR 完整在 HTML，收合以 CSS（`grid-template-rows 0fr→1fr`、opacity、`visibility:hidden` 不進 Tab 順序）；展開後焦點移到「相關內容」標題；網址 `#related` 直接展開（沒有 JS 時由 `:target` 展開、簡介文字完整顯示）。動畫 ≤ 240ms、無 `transition: all`、reduced-motion 只留 opacity。
- HTML 預算：每張相關卡約 415 bytes，最壞 11 組 × 24 ≈ 264 張約 110 KB＋基底約 62 KB ≈ 172 KB（依 fixture 推算，**真實資料尚未實測**，待確認）。

**封面圖**：IGDB 圖片 URL 換尺寸 token（`t_thumb`、`t_cover_big`、`t_1080p`）依 viewport 選用。著作權屬發行商，不做衍生用途，收到下架要求就下架。

## 活動

- 列表條件 `COALESCE(end_time, start_time) >= now()`，進行中的多日展會不會被藏起來。可依類型（發表會／展會／頒獎）篩選。

## 瀏覽與搜尋

- 排序 MVP 只開放 `popularity | release_date | name`，**不開放依評分**（D27）。
- **搜尋**：`games.searchText` = NFKC＋小寫，串接 `name`＋`alternativeNames`＋`game_localizations.name`，建 GIN trigram 索引，同步時更新。
- 🧪 **中日文**：資料庫必須是 UTF-8 locale（`C`／`POSIX` 下 `pg_trgm` 對中日文完全失效）；`C.UTF-8` 可用但相似度偏低，所以 `searchText` 與查詢字串都經同一個 `tokenizeForSearch()`：連續 CJK 字元拆成相鄰雙字（bigram），拉丁文不變。只輸入 1 個中文字時退回 `ILIKE`。不夠用再考慮 `pg_bigm`／PGroonga／Meilisearch（D28）。
- 搜尋不分語系，結果以當前語系名稱顯示；名稱排序以原文 `games.name`，UI 標示「依原文名稱排序」。
- 全站搜尋涵蓋遊戲、平台、公司、系列、活動。
- **HTML 預算 < 200 KB**（Z6 實測 `/games` 不分組：zh-Hant 167,026、en 165,666、ja 172,832 bytes）。伺服器元件的輸出會同時出現在 HTML 和 RSC payload，每個 React 元素在 payload 裡約佔 200 bytes。所以數量多的重複元素要壓低成本：
  - 篩選面板的核取方塊清單整段產生成一個已跳脫的 HTML 字串（`dangerouslySetInnerHTML`，內容全部經跳脫），不做成幾百個 React 元素；沒有 JS 也能送出。
  - 卡片用精簡的 class 與純 `<img>`。
  - 熱度圖示用同一頁共用的 SVG sprite。
  - 不分組的預設熱度排序寫 `popularity_score DESC NULLS LAST`，才用得到 `games_browse_pop_idx`（03）。
  - 一頁幾十筆以上的榜單／清單，改由客戶端元件吃緊湊的列（陣列，payload 每筆約 150 bytes），伺服器端照樣 SSR 成 HTML（`calendar/folded-cards.tsx`、`trending/trending-list.tsx`）。
  - 2026-10-29 全站量測（開發 DB 真實資料，HTML 含 payload 的 `<script>`；zh-Hant／en／ja）：`/trending` 251,762→163,147／250,088→161,093／254,721→165,901（改榜單為緊湊列＋共用熱度 sprite）；`/trending?group=released` 163,469／161,749／166,412；`/ratings` 168,061／166,558／172,601（完整平台清單）；`/games` 167,311／165,951／173,117；`/timeline` 約 135 KB；平台頁約 123 KB；公司頁約 106 KB；系列頁約 100 KB。量測工具：`node scripts/html-size.mjs <網址> <路徑…>`。
  - 鎖預算：`test/unit/html-budget-a.test.ts`（篩選面板與榜單的單位成本）、`e2e/html-budget-a.spec.ts`（fixture 下所有篩選頁 × 三語系 < 200,000 bytes；fixture 只有 3 個平台，真實資料量用上面的腳本量）。
  - 月曆頁的預算另計（約 250 KB，見 §月曆）：真實資料下 `/calendar` 約 200 KB；月份差很多，2026-12 未定日改只送前 24 款後由 711 KB 降到約 196 KB（2026-10-29 實測，見 §已知限制）。

## 互動背景、彩蛋與隱藏主題

D85、2026-10-23 實作；完整觸發表與解鎖對照見 `docs/design/easter-eggs.md`（本節只列要點與限制）。

- **背景**：手把按鍵符號（△○×□、ABXY、四款單臂十字鍵、類比搖桿蘑菇頭）緩慢漂浮的 canvas（`position:fixed; z-index:-1; pointer-events:none`）；游標靠近被推開（彈簧加阻尼）、點擊碎成粒子、數秒後在空白處重生。不使用漸層背景。程式碼分割、idle 才載入（約 20 KB），30 fps 上限，分頁隱藏時 0 幀；實測主執行緒占用約 3%、背景掛載後沒有 long task。
- **只在內容欄之外**：符號錨定在「可出現」的格子——寬螢幕只在 `main` 兩側留白（離欄緣 ≥ 24px）、窄螢幕與手機只在 hit test 判定為空白背景處；頁首內不出現。窄螢幕透明度 0.09、手機 0.07，且只留彩蛋需要的 13 顆符號。**背景不擋任何點擊**：只有點在「空白背景」（沒有實色背景／背景圖／backdrop-filter、不是可互動元件或媒體、無直接文字節點）才算點中符號。
- **`prefers-reduced-motion: reduce`**：背景靜止（彩蛋仍可觸發）、解鎖提示只淡入淡出、主題切換不做 crossfade。
- **彩蛋與解鎖**：依序點破符號、科納米密技、每日收集物（遊戲媒體演進 8 種）、閒置 60 秒聚成手把、波動拳指令、凌晨 2～4 點、隱藏成就（看過 50 款詳情、第一次訂閱 iCal、第一次追蹤、第一次建清單、全成就）、**在首頁**連點品牌 10 次（2 秒內；其他頁點品牌立即回首頁、不計數）。解鎖時右下角提示（`aria-live="polite"`，可關閉、6.5 秒自動消失、最多同時 3 則）。
- **9 個隱藏主題**（深海藍、翡翠綠、赤紅、8-bit、圖鑑完成金、待機暗紫、街機霓虹、夜貓子、Coding；名稱以配色描述，不使用商標圖形）：完整 token 在 `app/themes.css`，固定配色不隨系統；**全部通過 WCAG AA**（單元測試重算對比 ≥ 4.5、焦點框 ≥ 3，首頁與月曆各跑 axe 亮暗皆 0 違規）。只出現在主題下拉的「已解鎖」區：伺服器永遠只渲染 3 個基本選項，水合後依 localStorage 解鎖紀錄補上；`<html data-theme>` 可為這 9 個 key，`THEME_INIT_SCRIPT` 讀 `sok-unlocks` 判斷是否已解鎖，沒解鎖就當跟隨系統。
- **解鎖儲存**：未登入存瀏覽器 localStorage（`sok-unlocks`、`sok-egg-daily`、`sok-egg-viewed`）；登入後與帳號同步（聯集合併，09、07 `/me/unlocks`）。伺服器 HTML 不含任何使用者狀態、不送 Cookie，可快取。
- 測試掛鉤 `window.__eggTest` 只在 `NEXT_PUBLIC_EGG_TEST=1` 建置存在（e2e 用），production 建置編譯期移除。

## 多語系

**三條原則**

1. **網站語言是唯一語言來源**（D35）：右上角語言選單切換，我方控制的所有顯示內容一律用該語言。
2. **語言只由 URL 前綴決定**（D36）：同一網址不依 Cookie 或 `Accept-Language` 變內容，否則共用快取會把錯的語言給別人。
3. **資料庫不存已本地化的顯示字串**（D37）。

**無前綴入口（如 `/`）的語系決定順序**：Cookie `sok_locale` → `users.locale`（accounts 啟用時，經 `RequestContext`）→ `Accept-Language`（`zh-TW`／`zh-HK`／`zh-Hant` → `zh-Hant`；`en-*` → `en`；`ja*` → `ja`）→ `DEFAULT_LOCALE`（`zh-Hant`）。302 導向、`Cache-Control: private`、`Vary: Accept-Language, Cookie`。帶前綴的網址一律不導向，偏好與網址不同時以網址為準。

**語言選單**：一般連結（`<a href="/ja/<同一路徑>">`），不需要 JS；以各語言自稱顯示。點選時由專用端點寫 Cookie `sok_locale`（`SameSite=Lax`，1 年），登入者同時更新 `users.locale`。一般頁面回應不寫 Cookie（§SEO 與快取）。

**遊戲名稱解析鏈**（同步時預先算好寫入 `games.displayNames`，列表不必 JOIN）：

1. `game_localizations` 對應 locale 的名稱。IGDB 只提供 Japan → `ja`、Korea → `ko`（只存不顯示）；**沒有任何中文地區**，`zh-Hant` 名稱靠人工補登與使用者回報。
2. `alternativeNames` 中屬於該語系者：`comment` 是自由文字且繁簡標示不可靠，只標「Chinese title」的要人工確認才當 zh-Hant 顯示；標 simplified 的只當搜尋別名。腳本判斷（含假名 → ja）只作最後手段 ❓。不做簡轉繁。
3. `games.name`。

**格式化**

- `formatReleaseLabel(date, precision, locale)`：day → `dateStyle: 'long'`；month → `{ year, month: 'long' }`；quarter／year／tbd → 字典樣板。

  | | zh-Hant | en | ja |
  | --- | --- | --- | --- |
  | quarter | 2027 年第 2 季 | Q2 2027 | 2027年第2四半期 |
  | year | 2027 年 | 2027 | 2027年 |
  | tbd | 日期未定 | TBA | 未定 |

- **純日期用 `timeZone: 'UTC'` 格式化**，否則會因時區位移一天。活動等時間點依使用者時區（與語系無關）。
- 數字用 `Intl.NumberFormat`。官方 Node 映像為 full-icu ✅。

**字典**：`packages/i18n/messages/{locale}/{namespace}.json`，核心命名空間 `ui`、`enums`、`genres`、`themes`、`regions`、`ical`、`errors`、`filters`、`a11y`、`heat`；可選模組各自提供命名空間，移除模組時一併刪除。i18n 只依賴 `Intl`，網站與 Bot 共用（D38）。

## SEO 與快取

- 每個語系獨立網址＋`hreflang`＋`x-default`＋自我參照 canonical。
- sitemap 分片（單檔 ≤ 50,000 URL／50 MB ✅）＋ sitemap index，sitemap 以 `xhtml:link` 列各語系替代網址。
- 詳情頁 ISR（1~24 小時）＋`Cache-Control: s-maxage, stale-while-revalidate`。
- JSON-LD（`VideoGame`）、OG tags。
- **硬限制** ✅：回應帶 `Set-Cookie`，或 `Cache-Control` 為 `private`／`no-store`／`no-cache`／`max-age=0` 時 Cloudflare 不快取。**可快取頁面一律不送 `Set-Cookie`**。Cloudflare 規則見 16。
- 頁尾署名「Data from IGDB.com」。

## 已知限制（第二輪，2026-10-23 實測）

待使用者決定，也列入 15 的待辦：

- ~~`/games` 分組檢視查詢時間、平台頁 PC「全部遊戲」冷查詢、`/games` 不分組 HTML 約 239 KB~~：Z6（2026-10-24）已解決，見 §全部遊戲與分組檢視、§平台頁的「全部遊戲」、§瀏覽與搜尋。剩下的是每個查詢的第一次執行（PostgreSQL 快取還沒熱）大約是中位數的 2～6 倍，開發 DB 最多 1080 ms。分組檢視壓在 200,000 bytes 內（首屏每組 6 張、一頁 6 組是為此選的）。
- ~~評分排名頁篩選面板只列常用平台、`/trending` 約 301 KB~~：2026-10-29 已解決，見 §瀏覽與搜尋 的 HTML 預算（`/trending` 的主因其實是 50 筆榜單項目的元素樹與每筆一份火焰 path，不是篩選面板）。
- **月曆頁 HTML 隨月份差很大**（2026-10-29 部分解決）：摺起來的未定日大組（單組超過 `UNDATED_OPEN_MAX` 款）改只送前 24 款＋「查看全部 N 款」後，開發 DB 實測 2026-12 由 711 KB 降到 196 KB（en 189 KB）、2027-12 由 301 KB 降到 178 KB 以下，2026-10～11、2027-02～11 皆 < 230 KB。**仍略超 250 KB 的月份**：2026-08（zh-Hant 259／en 256／ja 264 KB）、2026-09（256／254／262 KB）、2027-01（254／252／259 KB）——原因不是摺起來的組，而是「數量 ≤ 24 的月精度組」以完整卡片展開（約 17～21 款，HTML 與 RSC payload 各一份約 50 KB 以上）加上格子；要再壓需把「展開成完整卡片」的門檻降到約 12 款以下（估算省約 40～50 KB，未實測），屬於 UX 決定，待使用者定案。
- **搜尋候選**：排序只在「符合者中熱度最高的 120 筆」內生效，另用 `lower(name)` 索引把「名稱完全相同」者補進候選；顯示名稱（非原名）完全相同但不在池內者不保證；`the`、`z` 這類短字約 250～580ms。`games(popularity_score DESC)` 索引因讓中等密度查詢（如 `final fantasy`）退步約 10 倍而不加；日後可改「先取最熱 2 萬筆，不足再退回全表」兩段式。
- **彩蛋背景**：1280px 這類內容欄幾乎等於視窗寬的桌機視為窄螢幕模式，符號仍可能出現在卡片之間的縫隙（空白背景）；手機空白區少時符號可能只有數顆。
- 公司頁、系列頁歸 GameBase 是實作判斷，改 `SECTION_ALIASES` 一行即可。

## 無障礙與響應式

目標 **WCAG 2.2 AA**（D52）。

- 手機寬度月曆改議程式清單。
- 觸控目標至少 24×24 CSS px ✅；主要操作建議 44×44。
- 月曆依 ARIA grid 模式：方向鍵移動、Enter 開啟；全站不靠滑鼠；焦點可見；「跳到主要內容」。
- 熱度、階段、延期／取消、遊玩狀態都有文字或圖示，不只靠顏色。
- 對比 ≥ 4.5:1（大字 3:1）；支援深色模式；尊重 `prefers-reduced-motion`。
- 篩選用原生 `fieldset`／`checkbox`；結果變更以 live region 告知筆數。
- 封面 `alt` = 遊戲顯示名稱；裝飾圖 `alt=""`；外語文字標 `lang`。
- 行動裝置 Core Web Vitals 達「良好」；圖片延遲載入、指定尺寸。
- CI 跑自動化檢查（`npm run test:a11y`，工具選型 ⚠️）；發布前人工檢查：純鍵盤走完月曆 → 詳情 → 追蹤，並抽查一種螢幕閱讀器。
