# 02 架構與模組

單一 Next.js 應用＋獨立的 Discord Bot process，是**模組化單體**，不是微服務（D10）。兩組規則：**分層**管一個功能內部的依賴方向；**模組**管功能之間的依賴。兩組都由 CI 強制（§CI 邊界檢查）。

## 分層

判斷一個東西易不易變：**它的定義是不是我們自己決定的？**「一款遊戲有名稱、上市日、分數」是我們對業務的理解，幾乎不變；「IGDB 用 unix timestamp 存日期」是第三方的技術決定，隨時會變。

```
Presentation（頁面、API route、Bot 指令、React 元件）       最常變
   ↓
Use Case（syncGames()、generateIcsFeed()、importOwnedGames()）
   ↓                    ↓
Repository（DB 查詢）    Provider（IGDB、Metacritic、Discord、Steam…）
   ↓                    ↓
Domain（Game、ReleaseEvent、Rating… 純型別，零外部依賴）     最穩定
```

| # | 規則 |
| --- | --- |
| 1 | Domain 不 import 其他層與第三方套件（zod 這類純驗證可例外） |
| 2 | Repository 可 import Domain 與 Drizzle；不 import Provider；`db.select()` 只能出現在 Repository |
| 3 | Provider 可 import Domain，回傳值轉成 Domain 型別；不 import Repository |
| 4 | Use Case 可 import Domain、Repository、Provider；不被 Repository／Provider 引用 |
| 5 | Presentation 只 import Use Case 與 Domain 型別；不 import Drizzle 或 Provider client |

| 情境 | 放哪層 |
| --- | --- |
| 「遊戲有 slug、name、封面」的型別 | Domain |
| IGDB timestamp 轉 `YYYY-MM-DD` | Provider（IGDB 那支檔案） |
| 把 IGDB 資料寫進資料庫 | Use Case（協調 Provider 與 Repository） |
| `SELECT … WHERE slug = ?` | Repository |
| 遊戲詳情頁元件 | Presentation |
| Metacritic HTML／JSON 解析 | Provider（可被一個開關整個關掉） |

**Domain 與 ORM 的折衷**：允許 Drizzle 的 `$inferSelect` 直接當 Domain 型別，省掉轉換層；但 import 規則照樣遵守。這是刻意的簡化，code review 時要知道它是折衷。

## 模組

| 模組 | 類型 | 內容 | 依賴 |
| --- | --- | --- | --- |
| `kernel` | 基礎 | DB 連線、env 驗證（fail closed）、排程註冊表、module registry、HTTP 快取工具、`RequestContext`、`/healthz` `/readyz` | 無 |
| `catalog` | **必選** | 遊戲／平台／上市日／活動／評分／比對的資料與同步、公開 API、月曆／時間軸／瀏覽／詳情頁、公開 iCal、資料更正回報 | kernel |
| `accounts` | 可選 | 登入與綁定、遊戲庫匯入、收藏清單、遊玩紀錄、追蹤、私人 iCal、帳號刪除 | kernel、catalog |
| `discord` | 可選 | `/api/v1/discord-*` 內部端點、Discord 相關表、網站上的「建立 Discord 活動」按鈕；Bot 本體是獨立 process | kernel、catalog、accounts（網站按鈕要辨識使用者的 Discord 身分） |
| `notifications` | 可選，預設關閉 | Email 與 Discord 私訊通知、偏好、退訂 | kernel、catalog、accounts |
| `awards` | 可選 | 頒獎典禮屆次、獎項、入圍、得獎 | kernel、catalog |
| `social` | 可選 | 公開評論、按讚、追蹤用戶、動態、封鎖、檢舉 | kernel、catalog、accounts |
| `metacritic` | 可選，預設關閉 | Metacritic 的 `RatingProvider` | kernel、catalog |
| `admin` | 可選，強烈建議啟用 | `/internal/*` 覆核、補登、審核、監控 | kernel、catalog |

`packages/i18n`、`packages/api-contract` 是跨 process 共用套件，不是模組。

### 邊界規則

1. `kernel` 不 import 任何模組。`catalog` 只 import `kernel`，**永遠不 import 可選模組**，也不為某個可選模組存在而改程式。
2. 可選模組只能 import `kernel`、`catalog` 及其 `requires` 列出的模組的**公開 API**（各模組 `index.ts`）；禁止深層 import。
3. 只有 `modules/registry.ts` 與 `app/` 的薄路由可以 import 可選模組。
4. 分層規則在每個模組內照樣適用。
5. 跨模組互動只有三種：公開 API（同步呼叫）、擴充點、`change_feed`（非同步，03）。
6. 被擁有者以外的模組只能讀別人的表，寫入要經擁有者的公開 API（表歸屬見 03）。

### 目前使用者：catalog 不依賴 accounts

`kernel` 定義 `RequestContext { currentUser?, locale?, preferredPlatformIds? }`。`accounts` 啟用時由它的 middleware 填入；未啟用時為空，`catalog` 照常運作。登入按鈕、追蹤與收藏按鈕經 UI slot 由 `accounts` 提供。

## Manifest 與擴充點

每個模組有 `module.ts`：

```typescript
export interface ModuleManifest {
  name: string;
  kind: "core" | "optional";
  requires: string[];               // 依賴模組；未啟用 → 拒絕啟動
  requiredEnv: string[];            // 模組啟用時才驗證；缺少 → 拒絕啟動
  ownedTables: string[];            // 移除模組時 drop
  jobs?: ScheduledJob[];
  ratingProviders?: RatingProvider[];
  popularitySignals?: PopularitySignal[];
  gameFilters?: GameFilterProvider[];
  uiSlots?: Partial<Record<UiSlotName, ComponentType>>;
  i18nNamespaces?: string[];
}

export interface ScheduledJob {
  name: string;                     // 同時是 advisory lock 名稱
  cron: string;
  lockMode?: "tx" | "session";      // 長任務用 session
  run(ctx: JobContext): Promise<void>;
}
```

```typescript
// modules/registry.ts —— 唯一會 import 可選模組的地方
const ALL = [catalog, accounts, discord, notifications, awards, social, metacritic, admin];

export function enabledModules(env = process.env): ModuleManifest[] {
  const listed = parseModules(env.MODULES);   // 未設定 → 預設清單；"none" → 空
  return ALL.filter((m) =>
    m.kind === "core" ||
    (m.name === "metacritic"
      ? env.METACRITIC_SCRAPE_ENABLED === "true"   // metacritic 只認這個開關
      : listed.has(m.name)));
}
```

**啟動檢查**：依序檢查每個已啟用模組的 `requires` 與 `requiredEnv`，並在 log 印出已啟用模組清單。

**薄路由**：`app/` 底下只做 re-export 並套用啟用檢查，首行註明所屬模組，方便移除時 grep：

```typescript
// @module discord
import { guardModule } from "@/kernel/modules/guard";   // 模組停用 → 404
import * as h from "@/modules/discord/api/discord-links";
export const GET = guardModule("discord", h.GET);
```

| 擴充點 | 提供者 | 例 |
| --- | --- | --- |
| `RatingProvider` | catalog | `metacritic` 註冊 `metacritic_scrape` |
| `ScheduledJob` | kernel | 各模組的同步、清理任務 |
| UI slot | catalog 版面 | `header.right`（登入）、`game.actions`（追蹤／收藏）、`game.sections`（頒獎、玩家評論） |
| `change_feed` | catalog | `notifications`、`discord`、`social` 讀取 |
| `PopularitySignal` | catalog | `accounts` 提供站內追蹤人數 |
| `GameFilterProvider` | catalog | `accounts` 提供 `mine=followed/owned/collected` |
| i18n 命名空間 | `packages/i18n` | `accounts.*`、`discord.*`、`awards.*` |

## 排程

- 各模組在 manifest 的 `jobs` 匯出任務；`kernel/scheduler` 在 `instrumentation.ts` 的 `register()` 內收集**已啟用模組**的任務，用 `node-cron` 註冊。
- 只在 Node runtime 執行（`NEXT_RUNTIME === 'nodejs'`，Node 專用模組在判斷內動態 `import()`）✅。Next.js 15 起 `instrumentation.ts` 預設啟用（15 以前需 `experimental.instrumentationHook`）；`register()` 每個實例各呼叫一次，所以多實例仍要靠 advisory lock。
- **鎖由 kernel 統一包**（advisory lock 規則見 04 §併發保護），任務本身不處理鎖；上一輪未結束時下一輪安靜跳過。
- 結果與耗時寫入 `sync_state`，供管理介面與告警使用。
- Discord Bot 的 reconcile 跑在 Bot process，不經這個註冊表。

```typescript
for (const job of enabledModules().flatMap((m) => m.jobs ?? [])) {
  cron.schedule(job.cron, () => withJobLock(job, () => job.run(ctx)));
}
```

## CI 邊界檢查

| # | 規則 | 時機 |
| --- | --- | --- |
| a | 分層規則 1~5 | 每次 push |
| b | 模組邊界規則 1~3 | 每次 push |
| c | `drizzle-orm` 與 `db.*` 只出現在 `repository/` 與 `kernel/db/` | 每次 push |
| d | core-only：`MODULES=none`、`METACRITIC_SCRAPE_ENABLED=false` 時型別檢查、測試、build 都通過 | 每次 push |
| e | 可移除性：對每個可選模組模擬移除後 `tsc --noEmit` 通過 | 每晚（選用） |

🧪 `dependency-cruiser` 能表達 a、b、c（需 TypeScript < 7，實測 6.0.3）。指令統一為 `npm run lint:arch`，**從 Phase 1 就啟用**。

```javascript
// .dependency-cruiser.cjs（路徑前綴依實際資料夾調整）
module.exports = { forbidden: [
  { name: "catalog-no-optional", severity: "error",
    from: { path: "^src/modules/catalog" },
    to: { path: "^src/modules/(accounts|discord|notifications|awards|social|admin|metacritic)" } },
  { name: "no-deep-import", severity: "error",
    from: { path: "^src/modules/([^/]+)/" },
    to: { path: "^src/modules/[^/]+/", pathNot: ["^src/modules/$1/", "^src/modules/[^/]+/index\\.ts$"] } },
  { name: "repo-no-usecase", severity: "error", from: { path: "/repository/" }, to: { path: "/use-cases/" } },
  { name: "drizzle-only-in-repository", severity: "error",
    from: { pathNot: "/repository/|/schema\\.ts$|kernel/db" }, to: { path: "node_modules/drizzle-orm" } },
], options: { doNotFollow: { path: "node_modules" }, tsPreCompilationDeps: true } };
```

## 追加與移除功能

| | 停用 | 移除 |
| --- | --- | --- |
| 做法 | 從 `MODULES` 拿掉 | 刪程式與資料 |
| 路由 | 回 404 | 刪除 |
| 排程／UI slot／擴充點 | 不註冊 | 刪除 |
| 資料表 | **保留**，可逆 | migration drop |

**追加**：建 `modules/<name>/`（各層＋`schema.ts`、`module.ts`、`index.ts`）→ manifest 宣告 `requires`、`requiredEnv`、`ownedTables` → 需要反應資料變動就讀 `change_feed`，不改同步程式 → `registry.ts` 加一行、`app/` 加薄路由 → 更新 03 表歸屬、16 環境變數、CI 可移除性檢查。

**移除**：先停用確認正常 → 刪資料夾、`grep "@module <name>"` 找出薄路由刪除、刪 `registry.ts` 那一行 → migration drop `ownedTables`（**會刪使用者資料**，先對照 09 §隱私、匯出、刪除）→ 刪環境變數與 i18n 命名空間 → 更新本規格。
