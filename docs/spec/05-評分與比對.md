# 05 評分與比對

評分來源只有兩個專業來源：**IGDB 分數**（預設、隨同步免費帶出）與 **Metacritic**（可選、預設關閉、Slice 3）。**玩家平均**另列，不進來源選單（D68，資料見 09）。不使用 RAWG（D59）。

## IGDB 分數

- `aggregated_rating`／`aggregated_rating_count` 隨 `games` 查詢帶出，同步時寫成 `scoreProvider='igdb'`、`scoreOrigin='igdb-aggregate'`、`scoreType='critic_aggregate'`、`platformId=NULL`、`reviewCount=aggregated_rating_count`。不另發請求、不進評分排程（`nextRefreshAt = NULL`）。
- 🧪 **0 不是分數**：`aggregated_rating_count` 為 0 或缺少時視為無分數，不寫列（或寫 `score=NULL`），**不可顯示成 0 分**。
- 只用 `aggregated_rating`；`total_rating` 的語意差異未確認 ❓。
- 樣本數少是已知限制：一律顯示 `reviewCount`；第一版不設「樣本少」門檻。

## Metacritic 抓取（`metacritic` 模組）

唯一被要求「可獨立關閉、預設關閉」的整合（原則三）。官方 API 經 Fabric Origin 付費提供，文件只列電影與影集；遊戲分數只能抓取，有使用條款與商標風險，且可能被封鎖、沒有事先警告（91 §Metacritic）。

**開關（兩道，都開才抓；2026-10-29 修訂，取代原本「唯一開關」）**：

1. 環境變數 `METACRITIC_SCRAPE_ENABLED=false`（預設），不受 `MODULES` 控制。false 時不註冊模組、不註冊 `sync_ratings`、`repair_matches_metacritic`、`refresh_metacritic_index`、不註冊排名欄，**對 metacritic.com 的請求數為 0**（整合測試以假 fetch 計數、e2e 以瀏覽器請求監控驗證，不能只看程式碼）。
2. 後台設定「允許抓取」（`metacritic.scrapeAllowed`，預設**關**；12 §設定頁）。環境變數開了、後台沒開＝模組載入但三個任務一律略過、HTTP 出口在每次請求前檢查、請求數同樣為 0。

兩者皆開才會對 metacritic.com 發出請求；此外被擋後有 24 小時冷卻（下述）。

**做法**

- 以 `RatingProvider` 實作，放 `modules/metacritic/provider.ts`，由 manifest 的 `ratingProviders` 註冊。
- **一次請求拿兩個分數**：metascore 與 user score，寫成兩列（`scoreType` 分別為 `metascore`、`user_score`）；user score 10 分制轉 100 分制。
- **只取數字**（分數、評論則數），**不存評論全文與評論者**，縮小版權曝露面。
- 請求路徑要在瀏覽器實際觀察，**每次啟用前都重做**，不照抄舊文件。2026-10-29 的觀察結果在 91 §Metacritic 實測：**遊戲頁是伺服器端渲染的 HTML**，Metascore 與玩家評分都在 `data-testid` 標記的區塊內（`product-score`、`user-reviews` 內的 `global-score-value-wrapper` 的 `title`），不需要呼叫站內的內部 API；`robots.txt` 對 `*` 禁止 `/search`。
- **slug 取得**：**不用站內搜尋**（`/search` 被 robots.txt 禁止）。改讀 robots.txt 列出的公開 sitemap（`/games.xml` → `/games/N.xml`，每片約 1000 個 `/game/<slug>/`），每週 `refresh_metacritic_index` 寫入本機表 `metacritic_slugs`（slug＋正規化名稱，pg_trgm 候選搜尋）；候選走 §標題比對 的信心評分與人工覆核，不得直接用猜測的 slug。slug 沒有年份，自動採用前先抓一次遊戲頁驗證上市年份（差距 > 2 年改進覆核）。
- 限速每秒不超過 1 次（請求間隔 ≥ 1.1 秒）、帶可辨識的 User-Agent（`GameDexBot/0.1 (+repo 網址; …)`，可用 `METACRITIC_USER_AGENT` 覆寫）、遵守 robots.txt（每 24 小時重讀；讀不到當作全部禁止）。429／5xx 依 `Retry-After` 或指數退避重試最多 2 次。
- **每日請求額度** `METACRITIC_DAILY_REQUEST_LIMIT`（預設 500，含 robots.txt、sitemap、驗證頁、分數頁），三個任務共用，存在 `sync_state`（`metacritic_budget`）；用完當天就停。每輪 `sync_ratings` 最多 100 款、`repair_matches_metacritic` 最多 200 款。
- **更新頻率**：`refresh_metacritic_index` 每週、`repair_matches_metacritic` 每日、`sync_ratings` 每小時（受每輪上限與每日額度限制）；每款遊戲的實際重抓間隔由 §分層排程 決定。
- **失效不升級**：403／401／驗證碼或 Cloudflare 挑戰頁一律停止，**不重試、不偽裝瀏覽器指紋、不輪替 IP、不解 CAPTCHA**；記 24 小時冷卻（`sync_state` `metacritic_blocked`，期間三個任務都不發請求）並送告警。頁面結構認不得（改版）回解析失敗，**不寫負向快取**（避免把整批標成沒有分數）；解析失敗率 ≥ 30%（至少 10 次嘗試）告警並停止本輪。
- 查無分數（頁面 `tbd` 或 404）寫負向快取（`score=NULL`＋`nextRefreshAt`）。
- UI 一律純文字顯示「Metascore」，**不用官方配色或 Logo**；附原頁連結與抓取日期。
- 移除模組時刪 `ratings`／`external_ids` 中 `metacritic_scrape` 的列，並 drop `metacritic_slugs`。
- 後台設定可關閉 Metascore／Userscore 的顯示（`ratings.showMetascore`、`ratings.showUserscore`，12 §設定頁）：關閉後 `selectRatings` 的 `hiddenScoreTypes` 把該類型從詳情頁分數區與排名頁欄位拿掉（不影響已存的資料）。

### 介面

```typescript
interface RatingResult {
  score: number;              // 正規化到 0~100
  scoreMax: number;           // 一律 100
  reviewCount: number | null;
  sourceUrl: string;
  scoreOrigin: string;        // 'metacritic' | …
  scoreType: "critic_aggregate" | "metascore" | "user_score";
  platformId: number | null;  // null = 來源不分平台
}
interface RatingProvider {
  readonly sourceName: string;
  findRatings(p: { name: string; releaseYear: number | null; igdbId: number }): Promise<RatingResult[]>;
  getScoreById?(externalId: string): Promise<RatingResult[]>;
  searchCandidates?(name: string): Promise<Candidate[]>;
}
```

換來源（例如談成 OpenCritic）只需實作這個介面並註冊，同步邏輯不改（D4）。

### 分層排程

只適用需要獨立請求的來源（目前只有 Metacritic），以 `ratings.nextRefreshAt` 實作，自然分散、沒有尖峰。

| 狀態 | 頻率 |
| --- | --- |
| 上市前超過 7 天 | 不抓 |
| 上市前 7 天 ~ 上市後 14 天 | 每天 |
| 上市後 15~90 天 | 每週 |
| 上市後 90 天 ~ 2 年 | 每月 |
| 超過 2 年 | 不排程 |

月精度以當月最後一天為基準、季／年以 `releaseDate`（期間最後一天）為基準，避免太早抓。

**選取查詢以 (遊戲, 來源) 為單位**（D30、D-Bug10）：否則 IGDB 列（`nextRefreshAt` 為 NULL）會讓 Metacritic 永遠不被抓。**查無分數也寫一列**（`score=NULL`＋`nextRefreshAt`，負向快取），否則同一批遊戲會永遠被重選。用 `EXISTS`，不用 `DISTINCT`（一款遊戲多列分數時批次大小會失真，D-Bug5）。

```sql
SELECT g.id FROM games g
WHERE <上市狀態落在上表窗口> AND g.game_type IN (<白名單>)
  AND ( NOT EXISTS (SELECT 1 FROM ratings r WHERE r.game_id = g.id AND r.score_provider = :provider)
        OR EXISTS (SELECT 1 FROM ratings r WHERE r.game_id = g.id AND r.score_provider = :provider
                   AND r.next_refresh_at < now()) )
ORDER BY g.popularity_score DESC, g.id
LIMIT :batch;
```

**資料流**：`repair_matches`（每日）負責模糊比對、寫 `external_ids`；`sync_ratings`（每小時）只對**已確認**（`needsReview=false`）的外部 ID 用 `getScoreById` 直接查分數，沒有就這輪跳過，不做即時模糊比對。兩者共用同一來源的每日請求額度。

**寫入**：`ratings` 已用 `UNIQUE NULLS NOT DISTINCT`（03），直接 `ON CONFLICT … DO UPDATE`。分數或評論數變動才寫 `score_snapshots`。

## 顯示規則

三層，**順序固定**：

| 層 | 誰決定 | 機制 | 作用 |
| --- | --- | --- | --- |
| 1 | 站長 | `VISIBLE_SCORE_PROVIDERS`，**後台設定 `ratings.visibleProviders` 有值就覆蓋**；另可在後台關掉 Metascore／Userscore（`hiddenScoreTypes`） | 哪些來源可以被看到、被選（硬限制；空字串／空清單 = 不過濾） |
| 2 | 使用者 | `scoreProviders` 偏好（預設 `['igdb']`） | 在第 1 層允許的來源中要看哪些 |
| 3 | 站長 | `RATING_DISPLAY_PRIORITY`（預設 `metacritic_scrape,igdb`），**後台設定 `ratings.priority` 有值就覆蓋** | 選了多個來源時誰當主分數 |

- 共用函式 `selectRatings(ratings, { visible, selected, priority })`，**頁面、API、App 都呼叫同一份**（原則五、D-Bug7）。先套 visible、再套 selected、最後選主分數；順序反了會讓被隱藏的來源被選成主分數。
- **主分數只從 critic 類型挑**（`metascore`／`critic_aggregate`），`user_score` 另列。
- 使用者選到的來源都沒分數時**不顯示分數**，不退回沒選的來源。
- **分數區永遠顯示**（D74）：沒有任何分數、或選到的來源都沒分數時，仍顯示分數區與目前選用來源的欄位，值為空白（視覺「—」、螢幕閱讀器讀「尚無評分」）；**不可顯示成 0 分**。JSON-LD 沒有分數時不輸出 `aggregateRating`。
- 訪客沒有偏好時預設 `['igdb']`；站長用第 1 層把 `igdb` 隱藏時，預設改為第 1 層允許的全部來源（否則預設什麼都看不到）。
- 選項只列實際存在的來源：Metacritic 未啟用或被隱藏就不出現；只剩一個來源時不顯示設定 UI。
- **儲存**：登入者存 `users.scoreProviders`；訪客存 `localStorage`。**不寫 Cookie**（可快取頁面不得送 `Set-Cookie`，06）。
- **與快取相容**（D60）：伺服器一律輸出第 1 層允許的所有來源分數，以 `data-score-provider` 標記，預設只顯示 IGDB，由小段客戶端腳本依偏好切換並重算主分數；沒有 JavaScript 時看到預設。JSON-LD 只用預設來源。
- 啟動時驗證兩個環境變數的 provider 名稱拼字，未知名稱就報錯。
- 每個分數標示來源與樣本數。瀏覽頁不開放「依評分排序」（D27）。
- 分段實作：訪客版屬 `catalog`；帳號儲存版屬 `accounts`。

**玩家平均**（D68）：由 `accounts` 經 UI slot `game.sections` 在詳情頁另一區塊顯示「玩家平均 8.5／10（123 人）」，人數低於 `PLAYER_RATING_MIN_COUNT`（預設 5）不顯示平均。不參與上表任何一層。第二輪起，達人數門檻的玩家平均另以 `score_provider=site_players` 每小時複製進 `ratings`（03 §評分、09），**只給評分排名頁排序用**（06），詳情頁讀 `ratings` 時排除此來源（玩家平均仍走 accounts 的 `game.sections`），因此不進來源選擇。

## 標題比對

IGDB 與 Metacritic、Steam、Xbox 是獨立的 ID 空間，只能靠「標題＋上市年份」模糊比對。`normalizeTitle`／`findBestMatch` 不論 Metacritic 是否啟用都要實作（遊戲庫匯入也用，09）。

### 正規化

```typescript
function normalizeTitle(title: string): string {
  // 先移除 ™®©：NFKC 會把 ™ 轉成 "TM"，之後就刪不掉（Phase 4 實測）
  let s = title.replace(/[™®©]/g, "").normalize("NFKC").toLowerCase(); // NFKC，不是 NFKD（NFKD 會拆掉日文濁音）；NFKC 後才轉小寫
  s = s.replace(/[À-ɏ]/g,                    // 只對拉丁擴充區去重音
    (ch) => ch.normalize("NFD").replace(/\p{M}/gu, ""));
  return s
    .replace(/&/g, " and ")
    .replace(/[:\-–—]/g, " ")
    .replace(/\b(deluxe|standard|ultimate|goty|game of the year|complete|definitive|remastered|edition)\b/g, "")
    .replace(/[^\p{L}\p{N}\s]/gu, "")                   // 保留 Unicode 字母數字（含中日韓），不用 \w
    .replace(/\s+/g, " ")
    .trim();
}
```

正規化後為**空字串一律視為無法比對**，不與任何字串視為相同（D29、D-Bug8：用 `\w` 會刪光中日韓字元，兩個空字串被判為相同而自動配對）。

### 信心評分

```
1. 我方 name 與所有 alternativeNames 各自對候選名稱比對，取最高
2. 正規化後任一方為空 → 該組不計
3. similarity = Levenshtein 相似度
   年份相同 +0.05；差距 > 2 年 −0.2；任一方年份 NULL 不加減；clamp 到 [0, 1]
   confidencePct = round(similarity × 100)
4. 一方的 token 集合是另一方的子集（原作 vs 續作／重製的特徵）→ 上限壓在 84
5. < 60 → 無候選（只記嘗試，不寫 external_ids）
   60~84 → needsReview = true
   ≥ 85 → 自動採用，但最佳與次佳差距 < 5 時仍 needsReview
6. （選用）平台重疊 +0.03
```

寧可少自動配對，也不要配錯遊戲。

### 修復排程 `repair_matches_{source}`

只在對應來源啟用時註冊。規則（D-Bug6、D-Bug9：沒有 cursor 時每次都撈到同一批）：

1. 不論成敗都寫 `external_match_attempts`。
2. 排序 `lastAttemptedAt NULLS FIRST, games.id`，最久沒試的優先。
3. 範圍限 §分層排程 的窗口＋白名單類型，不對全庫跑。
4. `matchMethod='manual'` 不覆寫；`external_id_rejections` 裡的候選不再提出。
5. 同一 `(source, externalId)` 被兩款以上遊戲配到 → 一律進覆核。
6. 每個來源有每日請求上限，額度用完就停。

```typescript
async function runRepair(source: string, batchSize: number) {
  const todo = await repo.findRepairCandidates(source, batchSize); // 上述 1~3 的查詢
  for (const game of todo) {
    if (!(await budget.tryConsume(source))) break;
    const rejected = await repo.getRejectedIds(game.id, source);
    const cands = (await provider.searchCandidates(game.name)).filter((c) => !rejected.has(c.externalId));
    const match = findBestMatch(game.name, game.altNames, extractYear(game.firstReleaseDate), cands);
    await repo.recordAttempt(game.id, source, !match ? "no_candidate" : match.needsReview ? "low_confidence" : "matched");
    if (match) await repo.upsertExternalId({ gameId: game.id, source, ...match }); // 不覆寫 manual
  }
}
```
