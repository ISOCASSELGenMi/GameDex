# 14 測試策略

**原則**：測試投資放在「錯了很難發現、後果嚴重」的地方，不追覆蓋率。Vitest；整合測試用真實的獨立測試資料庫，不 mock DB。第一版**不做**完整瀏覽器 e2e 矩陣、視覺回歸、效能測試（無障礙的純鍵盤 e2e 除外）。

## 單元測試

| 對象 | 必測案例 |
| --- | --- |
| `normalizeTitle()` | 中日韓標題保留（「ゼルダの伝説」不得變空字串）、濁音不被吃掉、重音去除、`&` ↔ `and`、空字串回傳「無法比對」 |
| `findBestMatch()` | 信心 clamp 到 100、< 60 視為無候選、子集上限 84、最佳與次佳差距、alternativeNames 參與比對 |
| `normalizeIgdbDate()` | `date_format` 0~7 每一種、2 月與閏年、UTC 午夜邊界（某月 1 日 00:00 UTC 不得算成上月）、未知值 → tbd |
| `resolveDateRange()` | 每種精度；整月事件 DTEND 為下月 1 日；季／年單日標記在期間最後一天 |
| `computeNextRefresh()` | 各評分排程層級；月精度以當月最後一天為基準 |
| 狀態機 | 延期 → delayed；delayed 日期過後 → released；cancelled 與復原 |
| 連結對照 | 未知 id → `other`，不讓同步出錯；商店去重 `(gameId, categoryLabel)` |
| `selectRatings()` | visible → selected → priority 順序；主分數只挑 critic 類型；選到的來源無分數時不顯示 |
| `requireInternalAuth()` | secret 未設或 < 32 字元 → 啟動失敗；送 `Bearer undefined` → 401 |
| `formatReleaseLabel()` | 5 種精度 × 3 語系；UTC-8 環境下 2026-10-01 仍顯示 10 月 1 日 |
| 語系協商 | `zh-TW`、`zh-HK`、`en-US`、`ja-JP`、`zh-CN`、`fr` 對照；帶前綴不導向；Cookie 與 `users.locale` 優先序 |
| 遊戲名稱解析鏈 | 有 localization、只有 alternative_names、都沒有 |
| `FilterSpec` | 同維度 OR、跨維度 AND；未知 slug 忽略並提示；超過 20 個值被拒 |
| 遊玩評分 | 1~20 半分換算；玩家平均一人一票 |

## 整合測試

**同步**
- diff：少了一列 → 標 removed，窗口外的資料不受影響；人工列不被動到。
- 同一 (平台, 地區) 同時有搶先體驗與正式版 → 兩筆並存；`unspecified` 變具體階段 → 視為更新。
- 日期變動 → `release_date_history`、`sequence + 1`、`change_feed` 在同一 transaction。
- 滾動校對可以標 removed；回填中斷可從 cursor 續傳，期間增量同步正常。
- 語言支援同步只取代 `igdb` 列；重複同步結果不變；IGDB 語言碼對 BCP-47（`zh-TW` → `zh-Hant`），對不上用 slug 保留。

**評分與比對**（僅 Metacritic 啟用時）
- IGDB 列存在時 Metacritic 仍被選中；查無分數寫負向快取後不再重選。
- `runRepair` 依 `lastAttemptedAt` 往前推進；否決的候選不再提出；`manual` 不被覆寫。
- 重複寫入同一分數不產生重複列（D-Bug3 回歸）。

**iCal**
- 日期異動後 UID 不變、SEQUENCE 遞增；取消／復原遞增。
- 延期成 tbd 後事件仍在且帶標記；延期到視窗外仍在（近 60 天改期）。
- `DTSTAMP` 取 `updatedAt`，重複產生內容位元組相同；ETag／304 正確。
- 同一事件在不同語系 feed 的 SUMMARY 不同、UID 相同。
- 私人 feed：追蹤遊戲／活動／平台各自正確輸出；token 重新產生後舊網址回空 ics。

**帳號與收藏**
- 解綁最後一種登入方式被拒；同一外部帳號不能綁兩個帳號。
- 清單可見度：private 匿名讀取 404、unlisted 憑 shareToken 可讀。
- 刪除帳號：關聯資料 cascade 清除、私人 feed 回 404、公開評論消失。
- 每日追蹤上限生效；停權帳號的追蹤不計熱度。

**Discord**
- 兩個並行請求對同一目標＋伺服器建立活動，只有一個呼叫 Discord（預留機制）。
- 未精確日期的上市事件無法建立活動。
- 手動刪除 Discord 活動後 reconcile 清除 link、不再重試；`removed` 不取消活動。
- 反應身分組到期自動清理；`change_feed` 變動對同一伺服器只發一次。

**通知**
- `dedupeKey` 防重複；被抑制的信箱不寄；雙重確認前不寄；一鍵退訂有效；彙整依用戶時區。
- 延期一筆被追蹤遊戲 → 下次彙整只收到一封。
- Discord 私訊失敗時改寄 Email。

**頒獎與社群**
- 同一獎項只能一個得獎者；遊戲頁列出入圍與得獎。
- 封鎖後互相看不到評論；按讚一人一次、不能讚自己；private 評論不出現在遊戲頁。

**回報**
- 日期類缺 `sourceUrl` 被拒；超過上限被擋；核可後 `manual` 優先、不被 diff 動到、寫 `change_feed` 且 `sequence + 1`；`takedown` 不公開。

## 模組化回歸

- **core-only**：`MODULES=none`、Metacritic 關閉時，月曆、時間軸、詳情頁、公開 iCal、公開 API 都可用，無任何路由或排程報錯。
- 停用模組的薄路由回 404、排程不註冊、UI slot 不渲染。
- `requires` 未滿足 → 啟動失敗；`requiredEnv` 缺少 → 啟動失敗（例：`discord` 啟用但缺 `INTERNAL_API_SECRET`）；模組停用時缺少不報錯。
- `npm run lint:arch` 對刻意違規的範例全部報錯。
- API 回應符合 `packages/api-contract` schema。
- 字典完整性：所有語系所有 key 都存在。

## 前端

- 同一頁面我方控制的內容不混語；不同語系網址不互相污染快取。
- 一款多平台遊戲在月曆／時間軸只出現一次。
- 熱度、階段、延期以圖示＋文字呈現；`heatLevel = 0` 不顯示；追蹤人數低於門檻為 `null`。
- 語言支援：無資料顯示「未提供資料」或「尚無語言資料」，不出現「不支援」。
- 篩選寫入 URL，重新整理、上一頁、切換月份後保持；常用平台標籤可清除；空結果列出條件；多維組合頁帶 `noindex`。
- 無障礙：關鍵頁面通過自動化檢查；純鍵盤走完月曆 → 詳情 → 追蹤；`prefers-reduced-motion` 生效。

### e2e 的時間

- e2e 的結果不得取決於幾點跑。共用 `test`（`e2e/support/helpers.ts`）有自動套用的 `fixedClock`：實際時間落在 UTC 02:00～03:59 時，瀏覽器的 `Date` 位移為同日 UTC 01:00（日期不變、差值固定、時間照常流動）；其餘時間不位移。測試中以 `browser.newContext()` 另開的 context（JS 啟用者）同樣套用。位移越小越安全，所以不固定成單一時刻；也不用 `context.clock.install`，它假造計時器，實測讓客戶端導覽的測試失敗。
- 起因：夜貓子彩蛋（本地 02:00～03:59 掛載時自動解鎖 `night-owl` 主題）在 UTC 02:00～03:59 讓主題選單多一個選項，整套 e2e 有 9 項穩定失敗（CI 同樣）。
- 需要指定時間的測試（夜貓子本身、隔日換收集物）在固定值之上用 `page.clock.setFixedTime` 覆蓋。`e2e/clock-e.spec.ts` 鎖住「一般頁面不會自動解鎖 night-owl」與位移邏輯本身。
