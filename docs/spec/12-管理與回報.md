# 12 管理介面與資料更正回報

## 管理介面（`admin`）

路徑 `/internal/*`。首版以 `ADMIN_BASIC_AUTH_USER`／`ADMIN_BASIC_AUTH_PASS` 保護（或改用 Cloudflare Access，免費 50 人 🔶）；**Slice 2 起改為登入帳號＋角色**（`admin`、`content_manager`，P44）。頁面 `Cache-Control: no-store`、POST 有 CSRF 防護、只走 HTTPS。`admin` 透過各模組的公開 API 修改資料，`catalog` 不知道它存在。停用時比對覆核佇列無法收斂，所以強烈建議啟用。

| 功能 | 說明 | 角色 |
| --- | --- | --- |
| 比對覆核 | ✅ `/internal/matches`（Metacritic 啟用時）：`needs_review` 佇列（信心由低到高）；確認、清除（同時寫 `external_id_rejections`，否則下次排程又提出同一錯誤候選；並刪除該遊戲的 Metacritic 分數列）、手動輸入外部 ID；確認與手動輸入標 `matchMethod='manual'`。「未配對遊戲」佇列（依熱度）尚未做 | admin |
| 上市日補登 | TW 等 IGDB 沒有的地區、`demo` 階段；`source='manual'` | admin、content_manager |
| 平台與活動編輯 | IGDB 沒收的主機與活動；活動類型、系列、主辦標註 | admin、content_manager |
| 頒獎名單 | 獎項、入圍、得獎（13） | admin、content_manager |
| 遊戲中文名稱 | 補登 `game_localizations`（zh-Hant） | admin、content_manager |
| 回報審核 | 見下 | admin、content_manager |
| 待回饋 IGDB | ✅ `/internal/igdb-feedback`：回報核可後的項目清單，手動到 IGDB 提交（見 §待回饋 IGDB 清單，D91） | admin |
| 社群檢舉 | 評論與用戶檢舉的處理（13） | admin |
| 帳號停權 | ✅ `/internal/users`：以信箱片段或 ID 搜尋、停權／解除、顯示狀態、註冊時間、有效登入數 | admin |
| 同步監控 | ✅ `/internal/sync`（唯讀）：各 `sync_state` 最後執行、回填進度（cursor／meta）、最近失敗、連續失敗次數；`rolling_refresh_misses` 沒有對應的表，未顯示 | admin |
| 網站設定 | ✅ `/internal/settings`：評分來源顯示、月曆預設、模組啟停（唯讀）、Metacritic 允許抓取、變更歷史（見下 §設定頁） | admin |
| 翻譯缺漏報告 | 缺翻譯的類型／主題、無中文名稱的熱門遊戲、字典檢查結果 | admin |
| 熱度分布 | `popularityScore` 與 `heatLevel` 直方圖、各訊號覆蓋率 | admin |
| 多餘的人工列 | `manual` 與 `igdb` 已一致的上市日，供定期清理（第一版不自動清） | admin |
| 通知統計 | 寄出／失敗／被抑制、各管道 | admin |
| Discord 伺服器 | `discord_guild_settings`、身分組與追蹤數量 | admin |

## 資料更正回報（`catalog`）

IGDB 日期常有誤或延遲，`TW` 等地區沒有來源，上市階段也可能缺漏；用回報讓使用者協助更正，取代「用戶直接編輯資料」（P28、D50）。

**入口**：遊戲詳情頁每筆上市日旁「回報資料有誤」、「補充我所在地區的上市日」；平台頁、活動頁、語言支援區也有。

```typescript
export const dataReports = pgTable("data_reports", {
  id: serial("id").primaryKey(),
  targetType: varchar("target_type", { length: 24 }).notNull(),  // 'release_event' | 'game' | 'platform' | 'event'
  targetId: integer("target_id"),                                // 新增型回報可為 NULL
  reportType: varchar("report_type", { length: 24 }).notNull(),  // 'wrong_date' | 'missing_region_date' | 'wrong_stage' | 'language_support' | 'cancelled' | 'localized_title' | 'duplicate' | 'takedown' | 'other'
  proposed: jsonb("proposed").$type<{ gameId?: number; platformId?: number; regionCode?: string; date?: string;
    precision?: string; stage?: string; language?: string; supportType?: string;
    title?: string; locale?: "zh-Hant" }>(),   // title／locale：localized_title
  sourceUrl: text("source_url"),         // 日期類必填
  note: text("note"),
  reporterUserId: integer("reporter_user_id"),       // 無 FK：catalog 不依賴 accounts，由 RequestContext 填
  reporterIpHash: varchar("reporter_ip_hash", { length: 64 }),  // 只存雜湊，保留 90 天
  status: varchar("status", { length: 12 }).notNull().default("open"), // 'open' | 'accepted' | 'rejected' | 'duplicate'
  resolutionNote: text("resolution_note"),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow(),
  resolvedAt: timestamp("resolved_at", { withTimezone: true }),
});
```

- **防濫用**：允許匿名（P17）；每 IP 每日上限 `REPORT_MAX_PER_IP_PER_DAY`（滾動 24 小時，任何狀態的回報都計入；先檢查上限再呼叫 Turnstile）；IP 以 `HMAC-SHA256(REPORT_IP_HASH_SECRET, IP)` 存雜湊（IPv6 取前 64 位；單純 SHA-256 可窮舉還原 IPv4），每日任務 `cleanup_report_ips` 把 90 天前的雜湊設 NULL；IP 取自 `CF-Connecting-IP` → `X-Forwarded-For` → `X-Real-IP`，正式環境必須在 Cloudflare／反向代理之後；人機驗證（Cloudflare Turnstile ✅ 免費、最多 20 個 widget）；登入者可放寬。表單提醒勿填個資。
- **流程**：`POST /api/v1/reports` → 佇列顯示「目前值 vs 提案值」、來源連結、同目標其他回報 → 核可／駁回／標重複。
- **核可**：經 `catalog` 公開 API 寫入或更新 `release_events`（`source='manual'`），**同一 transaction** 寫 `release_date_history` 與 `change_feed`，日期變動 `sequence + 1`——訂閱者的 iCal 與通知都會反映。新 manual 列的 `sequence` 至少為同 (遊戲, 平台, 階段) 各地區 igdb 列最大值 + 1，聚合輸出（iCal）不倒退。聚合時 `manual` 優先；詳情頁同 (平台, 地區, 階段) 有 active manual 列時不列 igdb 列。
- **IGDB 更新覆蓋人工更正**（D75）：同步時 igdb 對同一 (遊戲, 平台, 地區, 階段) **新建**列，或該列**日期／精度變動** → 同一 transaction 把該鍵 manual 列標 `removed`（寫 `change_feed`），igdb 列 `sequence` 設為 `max(現值, manual.sequence + 1)`。只有狀態變動、igdb 列被標 removed、或其他地區的變動都不覆蓋。之後再核可同鍵回報，manual 列重新 active。
- 回報類型與目標：`wrong_date`、`wrong_stage` 只對 `release_event`；`missing_region_date`、`language_support` 只對 `game`（`missing_region_date` 未指定階段時沿用同平台現有列的階段）；`cancelled` 對 `release_event` 或 `game`；`localized_title`（遊戲繁中標題，D91）只對 `game`；`duplicate` 四種皆可；`takedown`、`other` 可不指定目標。日期類 `sourceUrl` 必填，且只收 http(s)。`wrong_date`、`missing_region_date` 核可會自動改 `release_events`，`localized_title` 核可會寫 manual 的 zh-Hant 標題，其他類型核可只改狀態＋`resolutionNote`。除 `duplicate`、`takedown`、`other` 外，核可都會同一 transaction 建一筆待回饋 IGDB 項目（見 §待回饋 IGDB 清單）。
- **缺設定**：production 缺 Turnstile 金鑰或 `REPORT_IP_HASH_SECRET` → `POST /api/v1/reports` 回 503；非 production 跳過驗證並記 warn。`ADMIN_BASIC_AUTH_*` 未設或 `MODULES` 不含 admin → `/internal/*` 回 404（不回 401，避免彈出無法登入的對話框與洩漏路徑）；帳密錯 → 401。管理頁 POST 做同源檢查＋無狀態 HMAC token（CSRF）。
- 登入的回報者可看到處理狀態（選用）。
- **下架／版權請求**（`takedown`）：不公開顯示，直接通知站長（Email 或 `ALERT_WEBHOOK_URL`），結果記在 `resolutionNote`；收到要求就下架。

## 待回饋 IGDB 清單（`catalog` 表、`admin` 頁面；D91，2026-10-30）

回報核可後，自動產生一筆「待回饋 IGDB 項目」，集中在後台清單，讓管理者**手動**到 IGDB 網站提交修改。**程式完全不呼叫 IGDB 的任何寫入、不爬網站表單**；清單只放 IGDB 遊戲頁連結（`https://www.igdb.com/games/{slug}`，新分頁、`rel="noopener noreferrer"`），不猜編輯頁網址。`games.slug` 若因衝突帶 `-<igdbId>` 尾綴，產生連結時去掉。

**流程**：回報核可（同一 transaction 建項目）→ 後台 `/internal/igdb-feedback` 看卡片、複製整理文字到 IGDB 提交 → 標「已提交」→ 之後 IGDB 同步到相同內容時自動標「已被 IGDB 採納」。也可「略過」、「改回待回饋」。不補舊資料（只對上線後核可的回報建項目）。

**欄位登錄表**（`catalog/domain/igdb-feedback-fields.ts`，零外部依賴）：每個欄位鍵一筆，含顯示標籤、IGDB 頁面位置提示、對應回報類型、`build`（回報＋現況 → 項目內容的純函式，預覽與寫入同一份）、`formatValue`、`isAdopted`（採納偵測，純函式）。新增欄位＝加一筆登錄（必要時加回報類型與比對資料），不需要 migration（`field` 是 varchar）。第 1 波六個欄位：

| 欄位鍵 | 來自回報類型 | 舊值（核可當下快照） | 新值 | IGDB 已採納的判斷 |
| --- | --- | --- | --- | --- |
| `release_date` | `wrong_date` | 同鍵 igdb 列的日期＋精度（沒有則 null） | 提案的代表日期＋精度 | 同 (遊戲, 平台, 地區, 階段) 有 `source='igdb'`、`sourceStatus='active'` 的列，日期與精度相同 |
| `region_date` | `missing_region_date` | 同上（IGDB 無此地區上市日則 null） | 同上 | 同上 |
| `stage` | `wrong_stage` | 該列目前階段 | 提案階段 | 同 (遊戲, 平台, 地區) 有 igdb 列且階段等於新階段 |
| `language_support` | `language_support` | null | 語言＋支援類型 | igdb 來源的語言支援含該語言與類型 |
| `cancelled` | `cancelled` | 目標上市列狀態，或遊戲狀態 | `cancelled` | 目標是上市事件：igdb 同鍵列狀態為 cancelled；目標是遊戲：`games.gameStatus = 'cancelled'` |
| `localized_title` | `localized_title` | 核可前的 zh-Hant 顯示標題（可為 null） | 提案標題 | `alternativeNames` 或 igdb 來源的 `game_localizations` 有同名（NFKC、trim、忽略大小寫） |

`duplicate`、`takedown`、`other` 與任何駁回都不建項目。

**表 `igdb_feedback_items`**（migration 0021）：`id`、`report_id`（unique，FK→data_reports）、`game_id`（FK→games，cascade）、`igdb_game_id`、`game_slug`、`field`、`platform_id`／`region_code`／`stage`（定位用，可 null）、`old_value`／`new_value`（jsonb）、`source_url`、`reporter_note`、`status`（`pending`｜`submitted`｜`adopted`｜`skipped`，預設 pending）、`handler_note`、`created_at`、`updated_at`、`status_changed_at`、`adopted_at`。

**自動偵測**：`syncIgdbGame` 寫完一款遊戲後（同一 transaction）呼叫 `markAdoptedFeedback(tx, gameId)`：只查該遊戲 `pending`／`submitted` 的項目（走 `(game_id, status)` 索引，無項目只花一次查詢），有項目時各取一次上市列、語言、遊戲本體與在地化名稱，於記憶體依登錄表比對；符合就改 `adopted`＋`adopted_at`。`skipped` 不動。

**後台 `/internal/igdb-feedback`**：Basic auth → 同源 → CSRF；`no-store`＋`noindex`；狀態分頁含數量；卡片顯示遊戲（連我方詳情頁）、IGDB 遊戲頁連結、欄位與位置提示、平台／地區／階段、舊值→新值、佐證連結、回報者備註、來源回報錨點、唯讀整理文字 textarea（自行全選複製，不用客戶端 JS）；動作＝標為已提交／略過／改回待回饋，可勾選批次；寫入走 `POST /internal/igdb-feedback/action`；已被採納的項目不能手動改。審核頁已核可的回報卡片顯示「已建立待回饋 IGDB 項目」。

**`localized_title`（遊戲繁中標題）回報類型**：目標只能是 `game`（必填）；`proposed.title` 必填、trim 後 1～200 字；`proposed.locale` 目前只允許 `zh-Hant`；`sourceUrl` 選填（有填只收 http(s)）。核可：同一 transaction upsert `game_localizations`（`zh-Hant`、`source='manual'`，已有 manual 標題時覆蓋，舊值記在項目 `old_value`）、重算 `display_names` 與 `search_text`（與同步共用 `computeGameNames`），並建項目；核可後讓該遊戲詳情頁快取重建。同步不覆蓋 manual。

## 內部頁面共用導覽與設定頁（2026-10-29）

所有 `/internal/*` 頁面（回報、使用者、網站設定、同步監控；Metacritic 啟用時再多比對覆核）頂端有同一個共用導覽（`kernel/ui/admin-nav.tsx`），目前頁標 `aria-current="page"`，accounts 沒啟用就沒有「使用者」項。所有 POST 沿用同一套檢查：Basic auth（與 proxy 同一個函式）→ 同源 → CSRF token → 動作，回應 `no-store`＋`noindex`。

### 回報審核紀錄

已處理（已核可／已駁回／重複）的回報卡片顯示「審核紀錄」：結果、處理時間、處理備註、提案內容、核可後目前生效的 manual 上市列。**處理人沒有顯示**：`data_reports` 沒有處理人欄位，管理介面目前是單一 Basic auth 帳號，要記錄得加欄位（Slice 2 改帳號＋角色時一併做）。

### 設定頁 `/internal/settings`

設定存在 kernel 的 `app_settings`（鍵值＋jsonb），變更寫 `app_settings_audit`（誰＝Basic auth 使用者名稱、何時、舊值→新值；還原成預設也記一列）。架構理由見 02 §後台設定。每一組各一個表單（`POST /internal/settings/save`；Next 不允許同一路徑同時有 page 與 route，所以寫入走子路徑，比對覆核同理走 `POST /internal/matches/action`），可「儲存」或「還原成預設（環境變數）」：

| 組 | 鍵 | 說明 |
| --- | --- | --- |
| 評分來源顯示 | `ratings.visibleProviders`、`ratings.priority`、`ratings.showMetascore`、`ratings.showUserscore` | 取代僅環境變數的 `VISIBLE_SCORE_PROVIDERS`／`RATING_DISPLAY_PRIORITY`（環境變數是預設值，有 DB 值就覆蓋；空的可見清單＝不過濾；優先序至少一個來源）。詳情頁與 JSON-LD 在快取到期後生效，排名頁欄位即時（短 TTL） |
| 月曆預設 | `calendar.defaultGameTypes`、`calendar.defaultStages` | 取代 `CALENDAR_VISIBLE_GAME_TYPES`／`CALENDAR_VISIBLE_RELEASE_STAGES` 的預設；兩者各至少選一個；月曆、時間軸、瀏覽、公司／系列頁、詳情頁同系列、篩選面板的預設共用 |
| 模組 | （唯讀） | 列出各模組啟用狀態，註明需修改環境變數 `MODULES` 並重啟；不做執行期切換（02） |
| Metacritic | `metacritic.scrapeAllowed` | 第二道開關；環境變數 `METACRITIC_SCRAPE_ENABLED` 與此開關兩者皆開才會抓（05）。預設關 |

寫入前驗證：評分來源名稱必須是 `KNOWN_RATING_PROVIDERS`、遊戲類型是 `GAME_TYPES`、上市階段是 `RELEASE_STAGES`；不合法回設定頁並帶錯誤訊息，整批不寫。

### 同步監控 `/internal/sync`

唯讀。資料只來自 `sync_state`（每次任務執行後寫入的心跳與回填進度）與目前啟用模組註冊的排程任務清單：任務名稱、排程（cron／僅手動）、狀態（正常／失敗中／尚未執行／手動任務）、最後成功、最後失敗、連續失敗次數、cursor／meta 摘要；另列「最近失敗」（新到舊最多 10 筆，附錯誤訊息前 400 字）。
