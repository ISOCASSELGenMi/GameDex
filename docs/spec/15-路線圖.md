# 15 路線圖

Phase 是工作包，Slice 是上線批次。每個 Phase 有完成標準：「結束時系統能做到什麼」，不是「做了多少」。開發在本機（Windows）進行，完成後部署到 VM。

## Slice 與 Phase 對照

| Slice | 內容 | Phase |
| --- | --- | --- |
| 0 | 公開網站：月曆、議程式時間軸、詳情頁、基本篩選、三語系、IGDB 分數、公開 iCal | 0、1、2、3a、3b 的時間軸、3.5 的多語與快取、4 的 IGDB 分數、5 的公開 feed、9 |
| 1 | 帳號、收藏、遊玩紀錄、追蹤、私人 iCal、Email 通知、遊戲庫匯入；瀏覽與平台／公司／系列頁 | 3b 其餘、7、7.5 |
| 2 | 活動頁與頒獎、Discord Bot、Discord 私訊、內容管理員、管理介面與更正回報 | 4 的回報、8、8.5 |
| 3 | Metacritic、公開評論與按讚、追蹤用戶、動態、檢舉 | 6、6.5 |
| 之後 | 硬體世代時間軸、原生 App | 3c、10 |

## Slice 0

**目標**：能上線的「月曆＋時間軸」——公開網站、三個語系、公開 iCal（P25）。

| 做 | Phase |
| --- | --- |
| 環境、`kernel`＋`catalog` 的表、IGDB 同步（Tier 1、增量、滾動校對） | 0、1、2a |
| 月曆、遊戲詳情、基本篩選、聚合規則、i18n 骨架 | 3a |
| 議程式時間軸 | 3b 的一部分 |
| 繁中（主）、英、日：字典、類型／主題翻譯、`game_localizations`、`displayNames`、字典檢查 | 3.5 的 1、2 |
| ISR＋Cloudflare 快取＋rate limiting；hreflang＋canonical | 3.5 的 3、4 |
| IGDB 分數（含樣本數；只有一個來源，沒有來源選項 UI） | 4 的一部分 |
| 公開 iCal（未來 90 天）＋訂閱頁 | 5 的公開部分 |
| 部署、備份、CI、頁尾署名 | 9 |

**不做**：帳號相關、通知、Discord、Metacritic、webhook、公開 `/api/v1`、App、活動頁、硬體世代時間軸、瀏覽頁與平台／公司／系列頁（詳情頁先以純文字呈現）、sitemap 分片與 JSON-LD、管理介面與回報。其中活動頁、瀏覽與平台等頁、sitemap 與 JSON-LD 是建議，可調整。

**驗收**：三個語系下月曆、時間軸、詳情頁、公開 iCal 都正確；手動改一筆上市日後 `sequence` 遞增，訂閱者行事曆顯示新日期而非重複事件；同頁不混語、不同語系網址不互相污染快取；Cloudflare 快取命中；每日備份存在 VM 之外；頁尾有 IGDB 署名；維持非商業。

## Phase 0：環境

```bash
npx create-next-app@latest apps/web --typescript --tailwind --app --src-dir
npm install drizzle-orm pg ical-generator node-cron slugify
npm install -D drizzle-kit tsx @types/pg @types/node-cron
```

建 npm workspaces（`apps/web`、`packages/i18n`、`packages/api-contract`、`bots/discord-game-calendar`）；`drizzle.config.ts` 以 glob 載入各模組 `schema.ts`。本機 PostgreSQL 16（UTF-8 locale）。VM、DNS、防火牆等部署前再做（16）。

**完成**：`npm run dev` 能啟動並連上空的本機資料庫。

## Phase 1：Kernel、資料模型、CI 邊界

1. `kernel/`：db、config 驗證、scheduler 註冊表＋advisory lock、module registry、`RequestContext`、`/healthz` `/readyz`。
2. `modules/catalog/` 骨架與 03 的 catalog 表、索引總表、`updatedAt` 更新機制；migration；seed `regions`。
3. Repository 函式至少：`getGameBySlug`、`upsertGame`、`getReleaseEventsByMonth`、`upsertReleaseEvent`、`getRatingsByGame`、`upsertRating`。
4. `npm run lint:arch`（02 的 a、b、c）與 core-only CI job。
5. pg_trgm 中日文實測，結果記在 PR。

**完成**：所有 catalog 表與 seed 就緒；用 Repository 函式寫入並查出一筆測試遊戲，過程中 Repository 以外沒有 `db.select()`；刻意違規的範例被 `lint:arch` 擋下。

## Phase 2：IGDB 同步

到 Twitch Developer Console 註冊 Application 取 Client ID／Secret。實作 `providers/igdb.ts`（token 快取、4/s＋並發 8 節流、查詢）、`sync-games`、`sync-events`、`sync-platforms`。對照表已有實測值（04），不必再跑 spike。

- **2a**：平台同步＋Tier 1 回填＋增量同步＋上市階段＋語言支援資料（及早累積，量涵蓋度）。
- **2b**：Tier 2 回填＋相似遊戲與活動關聯批次解析＋滾動校對。回填以一次性 container 執行，先備份。

**完成**：
- 真實資料寫入；`release_events` 依平台／地區／階段正確拆分；公司、系列、連結、相似遊戲都有資料。
- 刻意製造「上市日消失」，驗證被標 `removed`，不是消失或仍為 active。
- 同一 (平台, 地區) 的搶先體驗與正式版並存。
- 回填中途停止後能從 cursor 續傳，期間增量同步正常。

## Phase 3：網站

- **3a**：月曆＋遊戲詳情（評分區先留空）＋聚合規則＋基本篩選（平台、平台類型、類型、階段；`FilterSpec` 放 `packages/api-contract`）。**同時建 i18n 骨架**：`[locale]` 路由、語言選單、字典與格式化函式（至少 zh-Hant＋en）——路由與字串晚做，所有連結與文字都要重寫。從 3a 起遵守無障礙要求，CI 加 `test:a11y`。
- **3b**：時間軸、完整篩選維度與 URL 狀態、瀏覽頁、平台／公司／系列頁、活動頁、熱度（`refresh_popularity`，此時只有 IGDB 與結構訊號）與熱門榜、語言支援區塊。
- **3c**：硬體世代時間軸（可後延）。

**完成**：看得到當月真實上市資料；詳情頁有商店連結、系列作品、相似遊戲；一款多平台遊戲只出現一次；熱門月份不被截斷到不可用；手機寬度月曆切為議程式；純鍵盤可走完月曆 → 詳情；熱度與階段以圖示＋文字顯示；語言缺資料時不出現「不支援」。

## Phase 3.5：多語補完、SEO、快取

1. `ja` 字典、類型／主題翻譯、`game_localizations` 與 `displayNames`。
2. 翻譯缺漏報告與 CI 字典完整性檢查。
3. sitemap 分片、canonical、hreflang（含 `x-default`）、JSON-LD。
4. ISR、Cloudflare Cache Rule 與 rate limiting。

**完成**：三語切換正確且同頁不混語；字典檢查通過；sitemap 被搜尋主控台接受；詳情頁命中快取且語系不互相污染。

## Phase 4：評分顯示、比對函式、回報

1. 確認 `sync-games` 已寫入 IGDB 分數列（0 不寫）。
2. `use-cases/matching/`：`normalizeTitle`、`findBestMatch`（遊戲庫匯入也用）。
3. `selectRatings`：頁面與 API 共用；訪客版來源選擇（`localStorage`）。
4. （Slice 2）資料更正回報：`data_reports`、`POST /api/v1/reports`、`/internal/reports`。

**完成**：詳情頁顯示 IGDB 分數與樣本數；沒有分數的遊戲不顯示分數區；`VISIBLE_SCORE_PROVIDERS`／`RATING_DISPLAY_PRIORITY` 分別測試符合 05；Metacritic 關閉時排程表裡沒有評分與比對任務；`normalizeTitle` 通過 CJK 案例。回報：核可一筆台灣上市日後以 `manual` 顯示、不被同步覆蓋、iCal `sequence` 遞增。

## Phase 5：iCal

1. **先做原型驗證**（設計未經客戶端實測）：用 Apple 與 Google 日曆各驗證 (a) 切換地區偏好後是更新還是重複建立、(b) 延期成 tbd 後事件仍在並顯示標記、(c) 取消後復原、(d) SEQUENCE 是否被採用。
2. `use-cases/ical/generate.ts`；公開 feed；ETag／304；訂閱頁（誠實的延遲文案、`webcal://`）。

**完成**：訂閱到 Apple 與 Google 各測一次；手動改日期後 sequence 遞增、行事曆顯示更新後日期而非重複事件；視窗離開規則、DTEND 排他、DTSTAMP／ETag 有測試；三語系輸出正確且標記來自字典。

## Phase 6：Metacritic（Slice 3）

1. 在瀏覽器開發者工具實際觀察 metacritic.com 的請求，不照抄舊文件。
2. `modules/metacritic/provider.ts`；註冊 `sync_ratings` 與 `repair_matches_metacritic`；管理介面的比對覆核。
3. 帳號版的來源選擇（`users.scoreProviders`）。

**完成**：開啟時正確抓到 metascore 與 user score；關閉（預設）時對 metacritic.com 的請求數為 0（用網路監控驗證）；IGDB 列存在時 Metacritic 仍被選中；查無分數寫負向快取；`runRepair` 往前推進；「清除配對」寫入否決表。

## Phase 6.5：社群（Slice 3）

`modules/social/`：遊戲頁公開評論列表、按讚、追蹤用戶、動態頁、封鎖、檢舉佇列。

**完成**：公開評論只顯示 public（及 followers 給追蹤者）；封鎖雙向生效；檢舉能在管理介面處理並隱藏內容；`social` 停用時評論只在作者個人頁可見。

## Phase 7：帳號、收藏、追蹤（Slice 1）

1. 認證函式庫選型；Discord、Google、Twitch、Email＋密碼登入；Twitter／X 與 Epic 先查證，不可行就跳過。
2. Steam（OpenID＋`GetOwnedGames`）、Xbox（OAuth → XASU → XSTS）登入與匯入；Steam 先用 AppID 精確比對，再 `findBestMatch`。
3. 清單、遊玩紀錄、玩家平均、追蹤（五種對象）、`mine` 篩選、常用平台。
4. 私人 iCal（`following` feed、token 可再顯示、重新產生）。
5. 追蹤熱度訊號（`site_follows`、`site_follows_7d`）、每日上限、追蹤人數顯示。
6. 隱私權政策、帳號刪除、資料匯出。

**完成**：各登入方式可用且可互相綁定；Steam／Xbox 匯入後看得到比對結果；追蹤的遊戲、活動、平台出現在個人 feed；`MODULES=none` 時網站仍完整可用；追蹤人數低於門檻不顯示；刪除帳號後私人 feed 回 404。

## Phase 7.5：通知（Slice 1 的 Email；Slice 2 的 Discord 私訊）

選 email 服務並設 SPF／DKIM／DMARC → 偏好、outbox、suppressions → 雙重確認與一鍵退訂 → `change_feed` consumer 與彙整 → 退信 webhook → 偏好設定頁；Slice 2 加 Discord 私訊管道。

**完成**：延期一筆追蹤遊戲後，下次彙整只收到一封；重跑任務不重複寄送；退訂後不再寄；`accounts` 未啟用時啟用 `notifications` 會啟動失敗；Discord 私訊失敗改寄 Email。

## Phase 8：Discord（Slice 2）

在 Discord Developer Portal 建**新的** Application。實作指令、建立活動（Bot 按鈕與網站按鈕）、reconcile、定時公告、伺服器共同追蹤、反應身分組；網站端 `modules/discord/` 與內部端點。

**完成**：兩個帳號**同時**對同一目標按建立，Discord 上只有一個活動；未精確日期無法建立；手動延期後一小時內（或手動觸發）活動時間更新；手動刪除活動後 reconcile 清除 link；`/language` 即時生效且所有文字用伺服器語系；公告依排程與篩選發出；身分組 30 天後自動清理；`discord` 停用時內部端點回 404；啟用但缺 `INTERNAL_API_SECRET` 時啟動失敗。

## Phase 8.5：頒獎與內容管理員（Slice 2）

`modules/awards/`、典禮頁、遊戲頁入圍得獎區、活動類型與系列標註；管理介面改為帳號＋角色（`admin`、`content_manager`）。

**完成**：內容管理員能建立一屆典禮的獎項與入圍、公布得獎；遊戲頁顯示紀錄；同一獎項只能一個得獎者；`awards` 停用時其他頁面正常。

## Phase 9：部署（第 16 章）

```bash
git clone <repo> && cd <repo>/infra
cp .env.example .env                 # 填入正式金鑰
docker compose up -d --build
docker compose exec web npx drizzle-kit migrate
docker compose exec web npx tsx src/modules/catalog/seed.ts
```

**完成**：正式網域可訪問；iCal 可被外部行事曆訂閱；（啟用時）Bot 在線；既有 TTS Bot 不受影響；Cloudflare 規則、Caddy 擋內部端點、全量回填前完成備份並確認可還原；流量分析、錯誤監控（含 scrub）、uptime 與任務心跳告警（**故意停一個任務確認收到告警**）、一次還原演練並記錄 RTO、服務條款與資料來源頁上線。

## Phase 10：原生 App

**前置**：`/api/v1/*` 已在正式環境穩定運作一段時間；先把 Web API 做好，App 只是另一個客戶端。

- 認證用 OAuth 2.0＋PKCE（原生 App 存不了 Client Secret），申請「原生應用程式」類型的用戶端。
- 優先包裝現有網頁（Tauri 桌面、Capacitor 行動），不整個用 React Native 重寫。
- 型別與 OpenAPI 取自 `packages/api-contract`。

**完成**：App 能登入、瀏覽月曆、訂閱個人 iCal（或把 feed 網址交給系統行事曆）。
