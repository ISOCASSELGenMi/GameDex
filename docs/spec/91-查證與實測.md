四輪 spike（2026-10-05 兩輪、10-07、10-08），以產品擁有者自己的 Twitch 憑證執行。

**欄位可用性**（第 1 輪，10 款即將上市主遊戲逐欄探測）
- 🧪 `category`（games、websites、external_games、release_dates）與 `release_dates.region` 可查但全空。
- 🧪 單數 `franchise`／`collection` 全空，複數 `franchises`／`collections` 有值，`name`、`slug` 可展開（第 2 輪）。
- 🧪 `follows` 樣本全空；`hypes` 10 款中 2 款有值。
- 🧪 `websites.type`、`external_games.external_game_source`、`release_dates.release_region`、`release_dates.status`、`game_type` 有值。
- 🧪 IGDB 分數三個欄位都可查；2 款有值的樣本是 0。

## 授權風險記錄

- ✅ IGDB 免費僅限非商業；商業需求聯絡 partner@igdb.com。
- 文件要求整合 API 的產品提供使用者看得到的署名；API 不允許瀏覽器直接請求（依 2026-09-29 的頁面複本與彙整頁核對，原頁面擋機器人）。
- 產品擁有者 2026-10-08 決定不寄信，理由：不對外提供 API；使用的 Node.js 客戶端函式庫是開源專案。
- **審閱註記**：函式庫的開源授權（MIT）不改變 IGDB 資料與 API 的條款，其 README 也沒有任何資料使用條款；Twitch 開發者條款有保存「Twitch 內容」副本的限制（論壇引文：除非書面授權、擁有權利，或只快取 24 小時且不提供給第三方），是否適用於 IGDB 資料**沒有明確答案**；「很多專案這樣做」不等於被允許。
- 「不對外提供 API」不涵蓋網站頁面與公開 iCal——它們仍是對外呈現衍生資料。降低疑慮的做法：Slice 0 不開 `/api/v1`、公開 iCal 只含 90 天、不提供全庫匯出、保留可清除全部衍生資料的能力。
- 非商業的做法：不放廣告、不做付費／訂閱、商店連結不帶聯盟參數（Twitch 條款有禁止用 API 資料推送商業優惠的規定，對 IGDB 的適用範圍不清楚）；捐款連結是否算商業沒有答案，第一版不放。
- 彙整頁稱所有端點有每日更新的 CSV 資料傾印；是否需要 partner 資格未確認。

**寄給 partner@igdb.com 的問題**（商業化或開放 API 前使用）

- We plan a public game database (web + API) covering historical and upcoming titles. Is it permitted to store a long-term copy of IGDB data in our own database, rather than only caching?
- May we expose our own public API that returns IGDB-derived data?
- What attribution do you require, and where?
- If the site is free but ad-supported later, which tier applies, and what are the terms?
- Are webhooks or data dumps available under a partner agreement?

- 「Metacritic」「Metascore」是註冊商標；Metacritic 屬 Fandom。
- 2026-10-12 當時沒有對 metacritic.com 發出任何請求；以下為 2026-10-29 Phase 6 第 1 步的實際觀察（內建瀏覽器＋3 個遊戲頁的單次請求，總共約 10 個請求，間隔 ≥ 1.5 秒，帶可辨識 UA `GameDexBot/0.1`）。**每次啟用前要重做一次**。

### 2026-10-29 觀察結果

- **robots.txt**（`/robots.txt`）：對 `User-agent: *` 禁止 `/search`、`/signup`、`/login`、`/user`、`/jl/`、`/8264/`、`/7336/`；`/game/` 與 sitemap 沒有被禁。列出 Sitemap：`/games.xml`（索引）等。GPTBot、CCBot 等有各自的全站禁止。**結論：站內搜尋不可用，改讀 sitemap。**
- **sitemap**：`/games.xml` 是 sitemapindex，指向 `/games/1.xml`…`/games/N.xml`（本次看到至少 39 片以上）；每片 1000 個 `<loc>https://www.metacritic.com/game/<slug>/</loc>`＋`changefreq weekly`，約 108 KB。slug 是標題的 kebab-case，沒有年份或平台。
- **遊戲頁** `https://www.metacritic.com/game/<slug>/`：HTTP 200、`text/html;charset=utf-8`、約 0.7 MB、Nuxt 伺服器端渲染（raw HTML 已含分數，不需執行 JavaScript、不需內部 API）；Cloudflare 在前面但**未出現驗證碼或挑戰頁**（以 Node fetch 與固定 UA 取得 200）。不存在的 slug 回 404（約 110 KB 的 Page Not Found 頁）；尚未上市的遊戲（例：grand-theft-auto-vi）回 200，分數值為 `tbd`。
- **分數所在**：
  - Metascore：`data-testid="product-score"` 區塊內，`global-score-header` 文字為 `Metascore`；`global-score-value-wrapper` 帶 `title="Metascore 97 out of 100"`／`aria-label`，值在 `<span data-testid="global-score-value">97</span>`；評論則數在 `global-score-review-count` 的連結文字「Based on 109 Critic Reviews」。
  - 玩家評分：`data-testid="user-reviews"` 區塊內同樣的 testid，`title="User score 8.9 out of 10"`，「Based on 27,453 User Ratings」。**10 分制**，我方以 100 分制存（×10 四捨五入）。
  - 上市年份：`<script type="application/ld+json">` 的 `VideoGame.datePublished`。
  - 頁面另有各平台的 `product-score-card`（各平台分數）；本次只取頁面層級的合併分數（`platformId=NULL`）。
- **沒有使用**：站內的內部 API（`backend.metacritic.com`／頁面 payload 裡的 `/metacritic/user/games/<slug>/stats/web` 之類）——那是未公開的介面，且頁面本身已含分數；評論全文與評論者（不存）。
- **風險仍在**：這些 `data-testid` 不是公開契約，改版就會失效（程式遇到認不得的結構回解析失敗、不寫負向快取、失敗率高時告警）；服務條款與商標風險不變（05）；站方隨時可能擋（程式遇 403／挑戰頁立即停止並冷卻 24 小時，不繞過）。
