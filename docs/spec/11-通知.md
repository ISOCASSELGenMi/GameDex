# 11 通知（`notifications`）

iCal 由客戶端拉取，延期可能隔天才出現在行事曆。通知是主動推送的補充，**不取代 iCal**（D51）。

**模組屬性**：可選、預設關閉（不在 `MODULES` 預設清單）；`requires: ['accounts']`；以 `change_feed` 驅動，不改同步程式。Email 管道啟用時 `requiredEnv` 含 `EMAIL_PROVIDER`、`EMAIL_FROM`、`EMAIL_API_KEY`；Discord 私訊管道需 `DISCORD_BOT_TOKEN`。

## 事件與管道

| 事件 | 對象 |
| --- | --- |
| 上市日確定（從模糊變確切） | 追蹤該遊戲，或追蹤其平台／系列／公司的用戶 |
| 改期、取消、復原 | 同上 |
| 即將上市（預設前 7 天與當天，`leadDays`） | 追蹤該遊戲的用戶 |
| 已上市 | 同上 |
| 活動即將開始（預設前 1 天） | 追蹤該活動的用戶 |

- 管道：**Email**、**Discord 私訊**（iCal 不需設定，隨追蹤自動更新）。每種事件可分別選管道（P31、FR-FOL-03）。
- 追蹤平台／系列／公司時，只通知「上市日確定」與「取消」，避免一次追蹤平台帶來大量信件。
- Email 可選**即時**或**每日彙整**；預設每日彙整，每人每天最多 `NOTIFICATIONS_MAX_PER_USER_PER_DAY` 封（預設 1）。Discord 私訊同樣預設彙整。

## 觸發

- **變動型**：consumer `notifications` 讀 `change_feed`（cursor 存 `consumer_cursors`），經 `accounts` 公開 API 查出相關用戶，依偏好過濾（排除停權帳號）後寫入 `notification_outbox`；`dedupeKey`（如 `userId:releaseEventId:type:date:channel`）防重複，`ON CONFLICT DO NOTHING`。
- **提醒型**：每小時，對「當地時間剛好到 `digestHourLocal`」的用戶（依 `users.timezone`），找 `release_date = 當地今天 + leadDays`、`precision='day'`、`status` 為 scheduled／delayed 的追蹤項目，套聚合規則與可見階段。
- **彙整**：把當天的變動與提醒合併成一封／一則。

## 資料表

```typescript
export const notificationPreferences = pgTable("notification_preferences", {
  userId: integer("user_id").primaryKey().references(() => users.id, { onDelete: "cascade" }),
  emailEnabled: boolean("email_enabled").notNull().default(false),       // 雙重確認後才為 true
  discordDmEnabled: boolean("discord_dm_enabled").notNull().default(false),
  channels: jsonb("channels").$type<Record<string, ("email" | "discord_dm")[]>>().notNull().default({}), // 事件 → 管道
  emailMode: varchar("email_mode", { length: 8 }).notNull().default("digest"),  // 'instant' | 'digest'
  leadDays: jsonb("lead_days").$type<number[]>().notNull().default([7, 0]),
  digestHourLocal: integer("digest_hour_local").notNull().default(9),
  updatedAt: timestamp("updated_at", { withTimezone: true }).defaultNow(),
});

export const notificationOutbox = pgTable("notification_outbox", {
  id: serial("id").primaryKey(),
  userId: integer("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  channel: varchar("channel", { length: 16 }).notNull(),     // 'email' | 'discord_dm'
  type: varchar("type", { length: 24 }).notNull(),           // 'date_confirmed' | 'date_changed' | 'cancelled' | 'release_reminder' | 'released' | 'event_reminder' | 'digest'
  dedupeKey: varchar("dedupe_key", { length: 160 }).notNull().unique(),
  payload: jsonb("payload").$type<Record<string, unknown>>(),
  scheduledFor: timestamp("scheduled_for", { withTimezone: true }).notNull(),
  status: varchar("status", { length: 12 }).notNull().default("pending"), // 'pending' | 'sent' | 'failed' | 'suppressed'
  attempts: integer("attempts").notNull().default(0),
  lastError: text("last_error"),
  sentAt: timestamp("sent_at", { withTimezone: true }),
});

export const emailSuppressions = pgTable("email_suppressions", {
  emailHash: varchar("email_hash", { length: 64 }).primaryKey(),   // 只存雜湊
  reason: varchar("reason", { length: 16 }).notNull(),              // 'bounce' | 'complaint' | 'unsubscribed'
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow(),
});
```

## 寄送

- 介面 `NotificationChannel.send(message)`，實作 `email`（託管服務或 SMTP，選型待定 P15）與 `discord_dm`（10 §Discord 私訊）。範本走字典 `notifications.*`，語系取 `users.locale`；Email 有純文字＋HTML。
- **Email 雙重確認**：開啟時寄確認信，點連結才生效；信箱未驗證不能開。
- **退訂**：每封信帶 `List-Unsubscribe`＋`List-Unsubscribe-Post`（一鍵退訂，RFC 8058 ✅）與可見的退訂、偏好連結。Gmail／Yahoo 自 2024 年 2 月起對大量寄件（每日 ≥ 5,000 封）要求 SPF＋DKIM＋DMARC、一鍵退訂、投訴率 < 0.3% ✅；小量也照做。
- 寄件網域設 SPF／DKIM／DMARC；退信與客訴經 webhook 寫入 `email_suppressions`，被抑制的信箱不再寄。
- Discord 私訊失敗（關閉私訊、不在共同伺服器）→ 該則標 `failed`，若已開啟 Email 改寄 Email，並在設定頁提示。
- 失敗重試指數退避，`attempts` ≤ 5，超過標 `failed` 並計入告警。

## 排程

`notifications-collect`（每 5 分鐘讀 `change_feed`）、`notifications-build-digest`（每小時）、`notifications-send`（每 5 分鐘）、`notifications-cleanup`（每日）。皆經 kernel 註冊表，鎖自動處理。

## 隱私

預設關閉、明確 opt-in；隱私權政策說明用途與退訂方式；帳號刪除時偏好與 outbox 隨 cascade 清除。各地商業郵件法規 ❓ 自行諮詢。

**後置**：Web Push（iOS Safari 條件 ❓）。
