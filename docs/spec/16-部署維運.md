# 16 部署與維運

自架在 Oracle Cloud VM（Ampere A1，D16），前面掛 Cloudflare（D17）。不拆服務、不用 Redis／BullMQ（D10）。

## 架構

```
使用者 → Cloudflare（代理模式＋CDN，免費方案）
       → Oracle VM
           ├─ Caddy（反向代理＋TLS，Cloudflare Origin CA 憑證）→ web:3000
           ├─ postgres（唯一真相來源，不對外）
           ├─ web（網站＋API＋iCal＋內建排程）
           ├─ discord-game-calendar（Bot，獨立 process）
           └─ 既有 TTS Bot（獨立部署，不受本 compose 管理，不要動）
```

## docker-compose

```yaml
# infra/docker-compose.yml
services:
  postgres:
    image: postgres:16            # Debian 版；alpine（musl）的中日文搜尋行為未測
    restart: unless-stopped
    environment:
      POSTGRES_USER: sok
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: sok_studio
      POSTGRES_INITDB_ARGS: "--encoding=UTF8 --locale=C.UTF-8"   # 不可用 C／POSIX（pg_trgm 對中日文失效）
    volumes: [postgres_data:/var/lib/postgresql/data]
    expose: ["5432"]

  web:
    build: { context: .., dockerfile: apps/web/Dockerfile }    # context = repo 根目錄（workspaces 的 packages/ 要進來）
    restart: unless-stopped
    env_file: .env
    environment:
      DATABASE_URL: postgres://sok:${POSTGRES_PASSWORD}@postgres:5432/sok_studio
    depends_on: [postgres]
    expose: ["3000"]

  discord-game-calendar:
    build: { context: .., dockerfile: bots/discord-game-calendar/Dockerfile }
    restart: unless-stopped
    env_file: .env
    environment: { SITE_API_BASE: "http://web:3000" }
    depends_on: [web]

volumes:
  postgres_data:
```

- postgres 與 web 都不直接對外，只有 Caddy 對外（縱深防禦）。
- Dockerfile 複製根目錄的 `package.json`／lockfile 與用到的 workspace 套件，`.dockerignore` 排除 `node_modules`；Bot 只打包它依賴的套件。具體寫法與 build cache ⛔ 動工時驗證。

## Caddy

```
# infra/Caddyfile
sok-studio.com, www.sok-studio.com {
    @internal path /api/v1/discord-*
    respond @internal 404          # 內部端點只給 Bot 走 docker 內網
    reverse_proxy web:3000
}
```

TLS 用 Cloudflare Origin CA 憑證（不是本機向 Let's Encrypt 要），搭配 Cloudflare 的 Full (Strict)。`/ical/u/*` 不寫 access log 或遮罩路徑。

## Cloudflare

- DNS 代理模式（橘色雲朵）**必須開啟**；TLS 選 Full (Strict)。
- **HTML 與 JSON 預設不快取** ✅：對 `/[locale]/games/*`、`/platforms/*`、`/companies/*`、`/franchises/*`、`/events/*` 建 Cache Rule，否則數十萬頁的爬蟲流量直接打到 VM。
- 公開 feed `/ical/{locale}/*` 邊緣快取 5 分鐘（`.ics` 是否在預設副檔名清單 ❓，一律明確建規則）；`/ical/u/*` 不快取、不記路徑。
- `/internal/*`、`/api/*`、`/[locale]/me/*`、`/[locale]/feed` 略過快取。
- 頁面以完整 URL 為快取鍵，不依 Cookie 或 `Accept-Language` 變內容；`/` 的語系導向不快取。
- rate limiting 規則與 `robots.txt`；登入、回報、建立 feed、按讚等寫入端點另設更嚴的限流。

## 防火牆

OCI 有兩層，**都要開 80／443**：雲端的 Security List／NSG，以及 VM 內的 `iptables`／`firewalld`。只開一層仍連不通。

## 備份

Oracle Always Free 有無預警調整資源或停用實例的紀錄，所以：

- 每日 `pg_dump`，**存放在 VM 之外**（例如 Object Storage），**加密**。
- 備份腳本用系統 cron，獨立於應用程式排程。
- 保留策略：7 天＋4 週＋6 個月（可調）；備份失敗納入告警。
- **每季還原演練**：在乾淨環境還原、跑 core-only smoke 測試、對照筆數，記錄實際 RTO。起始目標 RPO 24 小時、RTO 4 小時 ❓。
- 備份含個資：刪除帳號後，備份中的舊資料在保留期後自然過期，隱私權政策要如實說明。

## 部署檢查清單

1. DNS 生效（`dig` 回 Cloudflare IP）；兩層防火牆都開 80／443。
2. `.env` 對照下方環境變數表逐一填齊。
3. `docker compose ps` 全部 running；migration 與 seed 已執行。
4. 啟動 log 的「已啟用模組清單」符合預期，無 `requiredEnv` 缺漏。
5. 手動觸發一次 IGDB 同步，資料庫出現真實資料。
   - 從 migration 0014 以前的資料庫升上來時：最好在同步停止期間依序套 0015、0016，再跑 `npm run job -- backfill_game_groups`（04；約 32 萬款要 7 分鐘左右；任務不打 IGDB，但 catalog 啟動檢查仍需 IGDB 環境變數）。D88：再套 migration 0017，之後視需要跑 `npm run job -- backfill_company_positions`（04；會打 IGDB，需金鑰；沒跑時廠商分組退回舊規則，不會壞）。回填完成前 `/games?by=date｜publisher` 會全部歸成一組，平台頁「全部遊戲」會退回即時聚合（較慢）。回填結束後打開 `/games?by=date` 確認分組正常。
6. 網站正常；訂閱一個測試 feed 成功。
7. （啟用時）Bot 在線、`/upcoming` 有回應。
8. 既有 TTS Bot 正常。
9. `/healthz`、`/readyz` 正常；uptime 監測與告警通道通過測試；最近還原演練日期與 RTO 已記錄。

## CI／CD

每次 push（GitHub Actions）：

```yaml
jobs:
  check:
    steps:
      - run: npm ci                      # repo 根目錄，workspaces 共用 lockfile
      - run: npm -w apps/web run lint
      - run: npm -w apps/web exec tsc -- --noEmit
      - run: npm -w apps/web run i18n:check
      - run: npm -w apps/web run lint:arch
      - run: npm -w apps/web run test:a11y
      - run: npm -w apps/web exec vitest run
      - run: npm -w apps/web run api:check  # OpenAPI 產物是最新
      - run: npm -w apps/web run build
  core-only:
    env: { MODULES: "none", METACRITIC_SCRAPE_ENABLED: "false" }
    steps: [ npm ci, tsc --noEmit, vitest run, build ]
```

- 每晚（選用）：對每個可選模組跑 `scripts/check-removable.sh <module>`（依 02 的移除步驟模擬後 `tsc --noEmit`）；失敗代表有程式偷偷依賴該模組。
- 部署第一版**手動觸發**（VM 上 `git pull && docker compose up -d --build && … migrate`），不做 push 即部署；頻率高了再接 GitHub Actions＋SSH。不建 staging，直到真的需要。

## 營運

**流量分析**：不用 cookie、不蒐集個資的工具（Cloudflare Web Analytics 或自架 Umami／Plausible ❓；VM 資源有限，優先託管）。事件：搜尋、追蹤、收藏、訂閱 feed、語言切換、回報、開啟通知、建立 Discord 活動。不得送出個資、feed token、含 email 的 URL。是否需要同意橫幅依司法管轄 ❓。

**錯誤監控**：前後端與 Bot 都接（Sentry 或 GlitchTip ❓），事件帶 `module`、`job` 標籤，排程失敗要上報。`beforeSend` 必須清掉 `/ical/u/{token}`、`Authorization`、OAuth token、`INTERNAL_API_SECRET`、email、密碼欄位。

**Uptime 與告警**

- 外部監測每分鐘檢查 `/healthz` 與一個**經過 Cloudflare 的公開頁面**（同時偵測 CDN 與源站；也是發現 VM 被停用的第一道防線）。
- **任務心跳**：kernel 每次執行後寫 `sync_state.lastSuccessAt`／`lastFailureAt`／`lastError`；`now − lastSuccessAt > 2 × 預期間隔` 或連續失敗 ≥ 3 次就告警。
- 其他告警：備份失敗、磁碟 ≥ 85%、通知失敗率偏高、Bot 離線、Metacritic 解析失敗率偏高。
- 通道：`ALERT_WEBHOOK_URL`（例如 Discord webhook）與 Email。

**法務頁面**（三語）：隱私權政策、服務條款、資料來源與署名頁 `/about/data-sources`（IGDB；封面圖著作權屬發行商）、聯絡與下架申請（連到回報的 `takedown`）、cookie 說明。法律文件請諮詢專業人士，本規格只定義需要哪些頁面。
