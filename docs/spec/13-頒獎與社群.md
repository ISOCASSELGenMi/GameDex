# 13 頒獎與社群

兩個新的可選模組（P43）。各自停用時，其他功能不受影響（原則四）。

## 頒獎（`awards`）

**範圍**（P29）：頒獎典禮本身是 `catalog` 的 `events`（`kind='awards'`，屬某個 `event_series`）；`awards` 只管獎項、入圍與得獎。**IGDB 沒有這些資料**，全由管理員維護（Slice 2 起 `content_manager` 可維護，P44）。

```typescript
export const awardCategories = pgTable("award_categories", {
  id: serial("id").primaryKey(),
  eventId: integer("event_id").notNull().references(() => events.id, { onDelete: "cascade" }),  // 哪一屆
  name: varchar("name", { length: 255 }).notNull(),     // 獎項名稱原文（專有名詞，不翻譯）
  sortOrder: integer("sort_order").notNull().default(0),
  announcedAt: timestamp("announced_at", { withTimezone: true }),  // 得獎公布時間；NULL = 尚未公布
});

export const awardNominees = pgTable("award_nominees", {
  categoryId: integer("category_id").notNull().references(() => awardCategories.id, { onDelete: "cascade" }),
  gameId: integer("game_id").references(() => games.id, { onDelete: "cascade" }),
  nomineeLabel: varchar("nominee_label", { length: 255 }),  // 非遊戲的入圍者（人物、工作室）
  isWinner: boolean("is_winner").notNull().default(false),
  note: text("note"),
  sourceUrl: text("source_url"),                            // 官方公告連結
}, (t) => ({
  byGame: index().on(t.gameId),
  byCategory: index().on(t.categoryId),
}));
// CHECK: game_id 與 nominee_label 至少一個非 NULL
```

**顯示**

- 典禮頁 `/[locale]/awards/[series]/[year]`：時間、直播、各獎項的入圍名單，得獎者標示；未公布前只列入圍。
- 系列頁列出歷屆（FR-EVT-04）。
- 遊戲詳情頁「入圍與得獎」區塊（slot `game.sections`）：依年份新到舊。
- 得獎結果通知（追蹤該典禮的用戶）後置：需要 `awards` 對 `notifications` 發出事件的機制，首版不做。

**規則**

- 名單錄入必附官方來源連結；同一屆同一獎項只能一個 `isWinner`（應用層檢查，平手特例由管理員加註）。
- 獎項名稱是專有名詞，不翻譯；介面文字走 `awards.*` 字典。

## 社群（`social`）

**範圍**（P28）：公開評論與按讚、公開清單分享、追蹤其他用戶、動態、封鎖、檢舉。**評論內容存在 `accounts` 的 `play_records`**（評分＋評論＋可見度，09），`social` 負責公開呈現與互動，不重複存評論。`requires: ['accounts']`。

```typescript
export const reviewLikes = pgTable("review_likes", {
  userId: integer("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  playRecordId: integer("play_record_id").notNull().references(() => playRecords.id, { onDelete: "cascade" }),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow(),
}, (t) => ({ pk: primaryKey({ columns: [t.userId, t.playRecordId] }), byRecord: index().on(t.playRecordId) }));

export const userFollows = pgTable("user_follows", {
  followerId: integer("follower_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  followeeId: integer("followee_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow(),
}, (t) => ({ pk: primaryKey({ columns: [t.followerId, t.followeeId] }), byFollowee: index().on(t.followeeId) }));

export const userBlocks = pgTable("user_blocks", {
  blockerId: integer("blocker_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  blockedId: integer("blocked_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow(),
}, (t) => ({ pk: primaryKey({ columns: [t.blockerId, t.blockedId] }) }));

export const contentReports = pgTable("content_reports", {
  id: serial("id").primaryKey(),
  reporterId: integer("reporter_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  targetType: varchar("target_type", { length: 16 }).notNull(),  // 'review' | 'list' | 'user'
  targetId: integer("target_id").notNull(),
  reason: varchar("reason", { length: 24 }).notNull(),            // 'spam' | 'abuse' | 'spoiler' | 'other'
  note: text("note"),
  status: varchar("status", { length: 12 }).notNull().default("open"), // 'open' | 'actioned' | 'dismissed'
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow(),
});
```

**公開評論**

- 遊戲頁評論列表（slot `game.sections`）：只列 `reviewVisibility='public'`、作者未停權、未被檢舉處理隱藏的評論；可依讚數或時間排序；附作者的評分與遊玩狀態。
- 標劇透的評論預設折疊。
- `followers` 可見度：只有追蹤作者的人看得到。
- 按讚需登入，一人一讚；不能讚自己的評論。

**追蹤用戶與動態**

- 追蹤是單向的，不需對方同意；追蹤數與被追蹤數公開。誰追蹤了誰的名單是否公開 ❓ 待產品擁有者決定（遊戲追蹤清單一律不公開，D48）。
- 動態 `/[locale]/feed`：追蹤對象的新公開評論、新公開清單、遊玩狀態變成「玩完／全破」。**讀取時即時查詢**（經 `accounts` 公開 API 取最近的 `play_records` 與 `user_lists`），首版不建動態表；量大時再改寫入式。
- 動態只列對方設為公開（或 followers 且我有追蹤）的內容。

**封鎖與檢舉**

- 封鎖後：雙方互相看不到評論與動態、不能追蹤、不能按讚；不通知對方。
- 檢舉送進管理介面佇列（12）；處理方式：隱藏內容、停權帳號、駁回。
- 留言（評論的回覆）**不做**：需求沒有，且會大幅增加審核成本。

**防濫用**：評論與按讚設 rate limit；新帳號（例如註冊 24 小時內）的評論先不公開 ❓（待產品擁有者決定）。
