# 09 帳號、收藏、追蹤（`accounts`）

`accounts` 停用時，網站照常運作：header 只剩語言選單、沒有追蹤與收藏按鈕、只有公開 iCal。資料表見 03 §帳號、§收藏。

## 登入與綁定

| 方式 | 可行性 | 路徑 | 用途 |
| --- | --- | --- | --- |
| Discord | ✅ | OAuth 2.0，scope `identify email guilds` | 登入；網站「建立 Discord 活動」要用 `guilds` 判斷使用者在哪些伺服器有權限（10）；Discord 私訊（11） |
| Google | ✅ | OAuth 2.0 | 登入（沒有遊戲庫概念） |
| Twitch | ✅ ❓ | OAuth 2.0 | 登入；細節動工前查證 |
| Twitter／X | ❓ | OAuth 2.0 | 登入；開發者帳號條件與費用**未確認**，動工前查證，不可行就拿掉 |
| Email＋密碼 | ✅ | Better Auth（`connected_accounts` 的 `credential` 列） | 登入；`argon2id` 雜湊（D79）、信箱驗證、重設密碼 |
| Steam | ✅ 非標準 | 登入用 OpenID 2.0；`GetOwnedGames` 取遊戲庫 | 登入＋匯入；**使用者的 Steam 個人檔案必須公開**，UI 要明確提示 |
| Xbox | ✅ 較複雜 | Microsoft OAuth（provider `microsoft`）→ XASU → XSTS token 交換 | 登入＋匯入；先找維護中的開源實作參考 |
| Epic | ❓ | Epic Online Services 是否開放給非 Epic 遊戲的第三方查詢遊戲庫未確認 | 查證後決定 |
| PlayStation、Nintendo | ❌ | 無官方第三方管道；PSN 套件全是逆向工程 | 不做（D18） |

- **認證函式庫**：Better Auth（D76）。表對應見 03 §帳號；設定（argon2id、`storeIdentifier: "hashed"`、rate limit、lazy 單例）在 `modules/accounts/providers/auth/`。
- **沒有信箱的帳號**（Steam、部分 X 帳號）：`users.email` 填 `<外部 id>@<provider>.placeholder.invalid`、`emailVerified=false`（D77）；寄信、重設密碼、顯示信箱一律略過 placeholder（`isPlaceholderEmail()` 唯一實作）；使用者之後可改成真實信箱。
- **註冊開關**：`ACCOUNTS_SIGNUP_ENABLED`（預設 `false`）。隱私權政策、刪除帳號、資料匯出完成前不開放註冊（§隱私、匯出、刪除的前置條件）；關閉時註冊端點與入口都不出現，既有帳號仍可登入。條件：支援上表所有 provider 與 Email＋密碼、session 存資料庫、可客製 Steam OpenID。若函式庫需要自己的表，列入 `ownedTables`。
- **綁定**：同一帳號可綁多種方式；解綁時至少保留一種。已被其他帳號綁定的外部帳號不能再綁（`uniqueIndex(provider, providerAccountId)`）。
- **Email＋密碼**：註冊後寄驗證信，未驗證不能開啟 Email 通知；重設密碼 token 一次性、1 小時過期（BA `auth_verifications`，只存雜湊）；登入與重設端點設 rate limit（BA 內建）。寄信服務在 7.5，Phase 7 先以 `AccountMailer` 介面把連結寫到 server log。
- **Token 儲存**：`connected_accounts` 的 access／refresh／id token 以應用層 AES-256-GCM 加密（Better Auth 的 `databaseHooks`，不用 BA 內建以 AUTH_SECRET 加密的選項），金鑰 `TOKEN_ENCRYPTION_KEY` 與資料庫分開保管（是否用 KMS 依部署環境決定）。同一加密工具也用於 `calendar_feeds.tokenCiphertext`。
- 未來原生 App 用 OAuth 2.0＋PKCE，不能沿用網站的 Client Secret（15 Phase 10）。

## 遊戲庫匯入

平台給的是它自己的名稱與 ID，不能直接當 `games.id`。寫入 `owned_games` 時 `matchedGameId` 先為 NULL，以背景任務比對（使用者可能一次匯入幾百款，不要讓綁定流程等）：

1. **Steam 先精確比對**：用 AppID 對 `external_ids`（`source='steam'`），命中即信心 100。
2. 比不到的走 05 的 `findBestMatch()`（候選由 `games.search_text` trigram 取）；低信心不自動採用，在「我的遊戲庫」標示待確認，讓使用者自己指定（手動指定 UI 在 Phase 7 第 5 波）。
3. Xbox titleId 與 IGDB 的對應未驗證 ❓。

- 比對在匯入回應之後（`after()`）與排程 `match_owned_games`（每 15 分鐘、每批 500 列）進行。
- **每次匯入**把該帳號「找不到」的列重設為待比對，catalog 之後新增的遊戲因此有機會對上；待確認與已比對的列不動（D82）。
- Steam 回應中消失的遊戲（退款、移除）**保留**，不刪（D82）。
- 同一綁定帳號 10 分鐘內只能匯入一次。Steam 登入不需要 `STEAM_WEB_API_KEY`；沒有金鑰時匯入按鈕停用並說明原因。

匯入的遊戲可用篩選 `mine=owned` 找出；**不會自動加入任何清單或追蹤**。

## 收藏清單

- 多個具名清單：新增、改名、排序、刪除；同一遊戲可在多個清單；清單內可排序、加註。
- 可見度：`public`（個人頁列出、可被搜尋引擎索引）、`unlisted`（有分享網址才看得到，`shareToken`）、`private`。**預設私人**（P37）。
- 公開清單頁顯示建立者與遊戲卡片。
- 加進清單**不會**出現在行事曆（D19）；UI 要讓使用者分得清「收藏」與「追蹤」。

## 遊玩紀錄

以「用戶 × 遊戲」為單位，不隨清單複製；一款遊戲可多筆（二周目、換平台）。

| 欄位 | 規則 |
| --- | --- |
| 狀態 | 想玩、正在玩、玩完、全破、暫停、放棄（P36） |
| 平台 | 選填，限該遊戲有的平台 |
| 開始／完成日期 | 選填；完成日不得早於開始日 |
| 耗時 | 分鐘，選填 |
| 評分 | 0.5~10，半分一級（存 1~20，P42） |
| 評論 | 選填；可標劇透；可見度 `public`／`followers`／`private`，**預設公開**（P37） |
| 私人筆記 | 永遠不公開 |

- 遊戲詳情頁的動作列（slot）：「加入清單」「記錄遊玩」「追蹤」三個按鈕分開。
- **玩家平均**（D68）：`refresh_player_ratings` 每小時把每款遊戲「每位用戶最新一筆有評分的紀錄」彙整進 `game_player_ratings`（一人一票，避免多筆紀錄重複計分），停權帳號不計。站內平均耗時同理（FR-GAME-06）。顯示規則見 05。
- 公開評論的列表、按讚、檢舉由 `social` 提供（13）；`social` 停用時評論只在作者個人頁可見。
- 個人頁統計（各狀態數量、今年完成數、總耗時）即時聚合。
- **寫進 `ratings` 供排名頁使用**（第二輪）：排程 `publish_player_ratings`（每小時第 27 分，在 `refresh_player_ratings` 第 17 分之後；`lockMode: "session"`）把人數 ≥ `PLAYER_RATING_MIN_COUNT` 的玩家平均（平均 ×10，0～100 整數；人數為 `reviewCount`）經 catalog 的公開函式 `publishSitePlayerRatings` **整批取代**寫進 `ratings`（`score_provider=site_players`、`score_type=user_average`，03）；人數降到門檻以下的舊值一併刪除。catalog 的排名查詢只讀 `ratings`，不 import accounts。accounts 停用時任務不註冊，評分排名頁沒有玩家平均欄（06 §評分排名）。

## 解鎖紀錄、收藏與成就

彩蛋解鎖的主題、媒體收集物與隱藏成就（`docs/design/easter-eggs.md`），存 `user_unlocks`（03），同帳號跨裝置同步：

- **同步規則**：登入確定後，header 向瀏覽器的解鎖儲存註冊同步器；把 localStorage 的本機紀錄 `POST /api/v1/me/unlocks`（超過 100 筆分批），伺服器與帳號紀錄取**聯集**（同 `type`＋`key` 取較早的解鎖時間），回傳完整清單，瀏覽器合併寫回；之後每次本機新解鎖也 push。失敗（403 停權、網路、限流）不丟例外，紀錄留本機，下次再送。跨分頁用 `storage` 事件。登出或 accounts 停用時只存瀏覽器。
- **成就判定**：`viewed-50-games`、`first-ical-subscribe`（訂閱頁按複製／開啟）由瀏覽器判斷並 push；`first-follow`（有追蹤）、`first-list`（有清單）、`first-ical-subscribe`（`calendar_feeds` 有任一列，含已 revoked，取 `min(created_at)`）由**帳號資料**判定，在 `GET`／`POST /me/unlocks` 與資料匯出時即時補寫並持久化（之後取消追蹤或刪清單也不會失去成就；若追蹤後在任何一次 GET／POST／匯出之前就取消則不會記到，header 同步器每次載入頁面都會 push，實務上極少漏）。`all-achievements` 只有其餘四項都在帳號時伺服器才接受。
- **帳號頁「收藏與成就」**（總覽分頁內的區塊，不新增路由；停權者不顯示）：媒體 8 格（未收集顯示同形狀剪影與「？」，不顯示名稱）、已解鎖主題清單與「還有 N 個主題未解鎖」、已達成成就清單與「還有 N 個隱藏成就」；全成就時區塊有 3px 彩虹框線與「全成就達成」。靜態、無動畫；資料來自 `GET /me/unlocks`（帳號資料，不依賴 localStorage）。未解鎖項目不洩漏名稱與觸發條件。
- **匯出與刪除**：資料匯出 JSON 含 `unlocks`；刪除帳號 cascade。

## 追蹤

- 對象：遊戲、活動、平台、系列、公司（`follows.targetType`）。
- 追蹤 = 進個人 iCal（08）＋依偏好發通知（11）。
- 防灌水：每人每日新增上限 `FOLLOW_MAX_PER_DAY`（預設 200）。
- 追蹤清單**不公開**，對外只有聚合人數（D48）。
- 帳號總覽摘要的「追蹤」數**只算遊戲**（`countFollowsOfUser(userId, "game")`，D86），與「我的追蹤」主要內容一致；平台、系列、公司、活動的追蹤不計入摘要數字。
- 遊戲的追蹤人數經 `PopularitySignal` 提供給 `catalog` 算熱度（03 §熱度）；`catalog` 不 import `accounts`。
- `mine=followed` 篩選經 `GameFilterProvider` 提供。
- 每晚清理指向已刪除目標的孤兒列。

## 隱私、匯出、刪除

**啟用帳號系統前的前置條件**：

- **隱私權政策頁**：說明蒐集的資料（email、綁定帳號識別碼、遊戲庫、遊玩紀錄、公開與私人內容）、用途、保存方式、備份保留期。Google OAuth 審核會要求這個網址。
- **刪除帳號**：`DELETE /api/v1/account`，需重新驗證身分（重新登入或輸入密碼）。`users` 刪除後關聯資料由 cascade 清除；iCal 私人 feed 隨之失效（404）；公開評論一併刪除。
- **資料匯出**：清單、遊玩紀錄、追蹤、偏好，JSON 與 CSV。
- 停權（`users.suspendedAt`，由管理員操作）：追蹤不計熱度、不寄通知、公開內容隱藏。

## 管理角色

首版只有站長一人，用 Basic Auth 保護 `/internal/*`（12）。**Slice 2 起**加 `users.role = 'content_manager'`，讓多人維護頒獎名單與活動標註；`admin` 角色可指派。之後 `/internal/*` 改為登入帳號＋角色檢查（P44）。
