## 已定案的判斷（2a，使用者已同意）

- 平台上市日**只採原版機**：含全平台最早日期的版本，並列時一起採用。
- 手機平台照樣寫進 `platforms`（kind='mobile'），但手機平台的上市日、`game_platforms` 都不寫；只上手機的遊戲不收。
- `games.parentGameId` 存本體的 **IGDB id**。
- 遊戲層級 cancelled 也把 tbd 列標 cancelled；已過期的列不動。
- 新建上市列時直接判斷 released；「今天」用 UTC 日期。
- 增量同步第一次執行（沒有 sync_state）往回看 24 小時。
- Tier 1 的兩個條件都限白名單類型；回填每款一個 transaction、每批寫完才推進 cursor，失敗 id 記在 meta。
- 連結：未收錄的分類歸 `other`，每款只留一筆；Steam AppID 不因來源拿掉而刪；IGDB 分數消失時寫 NULL。

## Phase 2b 要做的事（spec/04、spec/15 §Phase 2、spec/03 §相似遊戲）

建議順序：1 → 2 → 4 → 3 → 5。

1. **`resolve_relations`**（tx lock；每日，回填每批後也跑）：
   - 規格 03 §相似遊戲的 SQL：`games.similar_igdb_ids` → `game_similar_games`。
   - ⚠️ 規格的 SQL 只 INSERT。相似清單改變時，舊的配對會留著，要不要刪除不在清單內的列，請先問使用者。
   - `event_games` 用同一套做法，等 sync_events 完成後加上。
   - 路線圖的完成標準要求「相似遊戲有資料」，目前 `game_similar_games` 是空的。
2. **Tier 2 回填**：
   - 條件：`where id > {cursor} & game_type = (白名單); sort id asc; limit 500`，約 32.7 萬款。
   - 建議擴充 `backfill-games.ts`：cursor 已有 `tier` 欄位，加 `--tier 2` 參數與對應 phase；寫入沿用 `writeGameBatch`，`markMissingRemoved: false`。
   - 每批寫完後跑 resolve_relations（規格要求）。考慮到成本，可改成每 N 批跑一次，要先問。
   - 預估 650 批，IGDB 單頁 2～14 秒加寫入約 5 秒，有預先抓下一頁，約 1～2 小時。在背景執行，並先備份。
3. **滾動校對 `rolling_refresh`**（session lock，每晚）：
   - 挑 `games.last_full_sync_at` 最舊的 `ROLLING_REFRESH_PER_NIGHT` 款，用 `fetchGames({ ids })`（每請求 500 個）重抓，`markMissingRemoved: true`。
   - `ROLLING_REFRESH_PER_NIGHT` 規格寫「實測後定」，env 還沒加，預設值要問使用者。
   - 監控指標 `rolling_refresh_misses`（寫進 `sync_state.meta`）：日期與 DB 不同、且不在最近增量名單內的筆數。「最近增量名單」怎麼判定沒寫死，可用 `games.updated_at` 或 `release_events.source_updated_at` 對照 `igdb_games.last_synced_at`，先提方案再做。
   - IGDB 已刪除的遊戲（以 id 查不到）怎麼處理規格沒寫，要問。
4. **`sync_events`**（tx lock，每 6 小時）：
   - `events` endpoint，欄位 `name, description, start_time, end_time, time_zone, event_logo.image_id, live_stream_url, games`，還沒實測，先用 probe 核對。
   - `GameDataProvider` 加 `fetchEvents({ updatedSince })`，Domain 加 `EventRecord`。
   - `source='manual'` 的活動不覆蓋、不刪除；`kind`／`seriesId` 由人工標註，同步不碰；`time_zone` 只存、不參與計算。
   - `games` 存進 `events.game_igdb_ids`，再由 resolve_relations 解析成 `event_games`。
   - `events.slug` 必填且 unique，沿用「撞名加 `-{igdbId}`」的慣例。
5. **2a 遺留**：`website_types`／`external_game_sources` 字典漂移偵測（04 §外部連結：每晚同步前抓字典比對，出現新 id 就記警告 log）。

Phase 2 的完成標準（15）還差兩項：相似遊戲要有資料（第 1 項），以及活動同步（第 4 項）。

## 地雷與慣例

- **規格書以 Project 正本為準**；兩項正本更新還沒做，等使用者處理：spec 04 §平台同步改成「只採原版機」、Project 的 `claude/checklist.md` 打勾。
- Bash 工具的 heredoc 遇到含中文、反引號或 `${}` 的長內容常常解析失敗。寫檔請用 Write／Edit 工具；臨時腳本放 scratchpad，DB 查詢在 `apps/web` 下用 `npx tsx --import ./scripts/load-env.ts <腳本>` 執行（腳本用 `require(process.cwd() + "/../../node_modules/pg")`）。
- tsx 跑 `.ts` 腳本不支援 top-level await，要包成 async 函式。
- Windows：用工具停止背景 shell 不會停掉子 node 行程（session lock 會被佔住），要再用 PowerShell 找出 `run-job` 的 node.exe 並結束它。
- 長任務（回填）用 Bash `run_in_background`，輸出導到 scratchpad 的 log 檔，再用 `until grep ...; do sleep 5; done` 的背景指令等它結束。
- 不要把 IGDB 憑證印出來（log 輸出時 grep 過濾 secret／token）。
- 整合測試用的 igdbId 要選不會和其他測試檔撞的範圍（目前用過 77xxxx、88xxxx、99xxxx、990xxx）。
