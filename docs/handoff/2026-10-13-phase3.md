## 已定案的判斷（使用者都已同意）

2a：
- 平台上市日只採原版機（含全平台最早日期的版本，並列時一起採用）。
- 手機平台寫進 `platforms`（kind='mobile'），但不寫上市日、不寫 `game_platforms`；只上手機的遊戲不收。
- `games.parentGameId` 存本體的 IGDB id（不設 FK）。
- 遊戲層級 cancelled 也把 tbd 列標 cancelled；已過期的列不動。新建上市列直接判斷 released；「今天」用 UTC 日期。
- 增量同步第一次執行往回看 24 小時。回填每款一個 transaction、每批寫完才推進 cursor，失敗 id 記在 meta。
- 連結：未收錄分類歸 `other`、每款每分類只留一筆；Steam AppID 不因來源拿掉而刪；IGDB 分數消失時寫 NULL。

2b：
- 相似清單／活動遊戲清單改變 → 刪除舊配對（人工活動的關聯不刪）。
- 回填每批只解析該批，整輪結束跑全量。
- `ROLLING_REFRESH_PER_NIGHT` = 10000。
- 滾動校對查不到的遊戲：保留遊戲，未上市（status ≠ released）的 igdb 上市列標 removed。
- `rolling_refresh_misses`：上市日有差異（新增、日期／階段、removed／restored；不含只有狀態推進），且來源 `updated_at` ≤ `igdb_games.lastSyncedAt`。
- 活動 change_feed：新活動 `created`、開始時間改變 `date_changed`。活動同步用增量。
- 字典漂移檢查在 `rolling_refresh` 開頭；連結的「未收錄」警告**只報已知清單以外的新 id**（已知清單：`link-map.ts` 的 `KNOWN_*_IDS`；出現警告就更新對照表與已知清單）。

## 地雷與慣例

- 規格書以 Project 正本為準；實作與規格衝突先問使用者。
- Bash 工具的 heredoc 遇到中文、反引號或 `${}` 常解析失敗：寫檔用 Write／Edit；臨時腳本放 scratchpad。
- DB 查詢腳本：在 `apps/web` 下 `npx tsx --import ./scripts/load-env.ts <腳本>`，腳本用 `require(process.cwd() + "/../../node_modules/pg")`；tsx 跑 `.ts` 不支援 top-level await，包成 async 函式。
- IGDB 實測：`npx tsx --import ./scripts/load-env.ts scripts/probe-igdb.ts <endpoint> "<apicalypse body>"`。
- 環境變數可在指令前覆寫（`ROLLING_REFRESH_PER_NIGHT=1000 npm run job -- rolling_refresh`）；`.env.local` 不會蓋掉。
- 長任務用 Bash `run_in_background`，輸出導到 scratchpad log，再用 `until grep ...; do sleep 10; done` 等它結束（前景 sleep 會被擋）。
- Windows：停止背景 shell 不會停掉子 node 行程（session lock 會被佔住），要用 PowerShell 找出 `run-job` 的 node.exe 結束它。
- 兩個 IGDB 長任務不要同時跑（各自節流 2/s，合起來會撞 IGDB 4/s 上限）。
- embedded-postgres 沒有 `pg_dump`；備份用 `CREATE DATABASE x TEMPLATE y`（來源不能有連線）。
- 不要把 IGDB 憑證印出來（log 輸出 grep 過濾 secret／token）。
- 整合測試 igdbId 範圍不要撞：已用 66xxxx、77xxxx、88xxxx、99xxxx、990xxx；整合測試檔案循序執行（`fileParallelism: false`）。
- 測試的假 Provider 必須實作 `fetchEvents`（`GameDataProvider` 介面）。
